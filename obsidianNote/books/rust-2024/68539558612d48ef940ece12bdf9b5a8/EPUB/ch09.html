Rust 中的结构体类似于 C 和 C++中的类，而 Python 中的类则类似于 JavaScript 中的对象。一个结构体可以将多种不同类型的值组合在一起，形成一个单一的值，从而可以作为一个整体来处理。对于结构体，我们可以读取和修改其各个组成部分。此外，结构体还可以拥有与其关联的方法，这些方法可以作用于其各个组成部分。

定义结构体


定义结构体类型最常见的方法如下：

/// A rectangle of eight-bit grayscale pixels.
struct GrayscaleMap {
    pixels: Vec<u8>,
    size: (usize, usize),
}

这定义了一个类型 GrayscaleMap ，该类型包含两个字段，分别名为 pixels 和 size ，且这两个字段的类型也是给定的类型。在 Rust 语言中，所有的类型，包括结构体，其命名规则都是每个词的第一个字母大写，这种命名方式被称为 UpperCamelCase 。而字段和函数的命名则使用小写字母，并且单词之间用下划线分隔。这种命名方式被称为 snake_case 。


你可以使用结构体表达式来构造这种类型的变量，如下所示：

let width = 1024;
let height = 576;
let image = GrayscaleMap {
    pixels: vec![0; width * height],
    size: (width, height),
};


结构表达式以类型名称开头（ GrayscaleMap ），然后列出每个字段的名称和值，所有内容都位于大括号之间。此外，还有一种简略方式来填充来自局部变量或参数的字段，即使用相同的名称来表示这些字段。

fn new_map(size: (usize, usize), pixels: Vec<u8>) -> GrayscaleMap {
    assert_eq!(pixels.len(), size.0 * size.1);
    GrayscaleMap { pixels, size }
}


结构表达式 GrayscaleMap { pixels, size } 实际上是 GrayscaleMap { pixels: pixels, size: size } 的简写形式。在同一结构表达式中，你可以对某些字段使用 key: value 语法，作为简写形式来表示这些字段。

assert_eq!(image.size, (1024, 576));
assert_eq!(image.pixels.len(), 1024 * 576);

和其他元素一样，结构体在默认情况下也是私有的，只有在其被定义的模块及其子模块中才能看到。如果你希望让结构体在模块外部可见，可以在其定义前加上 pub 前缀。其各个字段也是如此，这些字段在默认情况下也是私有的。

/// A rectangle of eight-bit grayscale pixels.
pub struct GrayscaleMap {
    pub pixels: Vec<u8>,
    pub size: (usize, usize),
}

即使一个结构体被声明为 pub ，其字段仍然可以是私有的：

/// A rectangle of eight-bit grayscale pixels.
pub struct GrayscaleMap {
    pixels: Vec<u8>,
    size: (usize, usize),
}


其他模块可以使用这个结构体，也可以调用其所有的公共相关函数。但是，它们无法通过名称访问结构体的私有字段，也无法使用结构体表达式来创建新的结构体实例。也就是说，要创建一个结构体实例，必须让结构体的所有字段都可见。因此，无法使用结构体表达式来创建新的 String 或 Vec 实例。这些标准类型本身就是结构体，但它们的所有字段都是私有的。要创建结构体实例，必须使用像 Vec::new() 这样的公共相关函数。

// In this game, brooms are monsters. You'll see.
struct Broom {
    name: String,
    height: u32,
    health: u32,
    position: (f32, f32, f32),
    intent: BroomIntent,
}

/// Two possible alternatives for what a `Broom` could be working on.
#[derive(Copy, Clone)]
enum BroomIntent {
    FetchWater,
    DumpWater,
}


最适合程序员的童话故事是《巫师的学徒》：一个初出茅庐的魔法师让一根扫帚为他完成工作，但当他完成任务后，却不知道如何停止这一行为。他用斧头把扫帚砍成两半，结果却得到了两根尺寸减半的扫帚。不过，他仍然以同样狂热的投入精神继续着这项任务……

// Receive the input Broom by value, taking ownership.
fn chop(b: Broom) -> (Broom, Broom) {
    // Initialize `broom1` mostly from `b`, changing only `height`. Since
    // `String` is not `Copy`, `broom1` takes ownership of `b`'s name.
    let mut broom1 = Broom {
        height: b.height / 2,
        ..b
    };

    // Initialize `broom2` mostly from `broom1`. Since `String` is not
    // `Copy`, we must clone `name` explicitly.
    let mut broom2 = Broom {
        name: broom1.name.clone(),
        ..broom1
    };

    // Give each fragment a distinct name.
    broom1.name.push_str(" I");
    broom2.name.push_str(" II");

    (broom1, broom2)
}


有了这个定义之后，我们可以制作一把扫帚，将其切成两半，然后看看会得到什么：

let hokey = Broom {
    name: "Hokey".to_string(),
    height: 60,
    health: 100,
    position: (100.0, 200.0, 0.0),
    intent: BroomIntent::FetchWater,
};

let (hokey1, hokey2) = chop(hokey);
assert_eq!(hokey1.name, "Hokey I");
assert_eq!(hokey1.height, 30);
assert_eq!(hokey1.health, 100);

assert_eq!(hokey2.name, "Hokey II");
assert_eq!(hokey2.height, 30);
assert_eq!(hokey2.health, 100);


新的 hokey1 和 hokey2 灌木已经获得了调整后的名称，高度减半，但健康值仍然与原始版本相同。

其他类型的结构


上述所讨论的结构类型被称为有名称字段的结构体。虽然这些结构体是 Rust 程序员最常遇到的结构类型，但实际上还有两种更简单的结构类型，分别称为元组结构体和类似单元的结构体。这两种类型在功能以及内存表示方式上都与有名称字段的结构体非常相似。

元组结构


第二种结构类型被称为元组结构体，因为它类似于元组。

struct Bounds(usize, usize);

你构建这种类型的值的方式，就跟构建元组一样。不过，你必须在其中包含结构体名称：

let image_bounds = Bounds(1024, 768);

可以通过常用的元组语法来访问元组结构中的各个字段：

assert_eq!(image_bounds.0 * image_bounds.1, 786432);

元组结构中的各个字段可以是公开的，也可以是不公开的：

pub struct Bounds(pub usize, pub usize);

表达式 Bounds(1024, 768) 看起来像是一个函数调用，实际上也是如此：定义类型的同时，也隐式地定义了一个函数。

fn Bounds(elem0: usize, elem1: usize) -> Bounds { ... }


元组结构适用于新类型的数据，尤其是那些由单一组件构成的结构体，这样能够提供更严格的类型检查。例如，如果你处理的是仅包含 ASCII 字符的文本，你可以这样定义一个新类型：

struct Ascii(Vec<u8>);


使用这种新类型来表示 ASCII 字符串，比使用 Vec<u8> 这样的缓冲区并在注释中说明它们是什么要更好得多。这种新类型有助于 Rust 在出现错误时能够及时纠正，因为可以避免在将某些字节缓冲区传递给函数时可能出现的错误。我们将在第 23 章中进一步讨论这个例子。

struct StudentId(u32);
struct CourseId(u32);

fn enroll(s: StudentId, c: CourseId) {
    ...
}

在这段代码中，你可以直接使用 u32 作为两个参数的占位符。不过，如果你使用了 newtypes，那么当调用者不小心反序传递参数时，Rust 系统仍然能够识别并纠正这个错误。

不过，有一点需要提醒一下。元组结构本质上和普通的命名字段结构是一样的，但是元组结构的字段名称都是一些无意义的整数。除了新类型的数据结构之外，我们发现自己常常后悔使用了元组结构，因此通常会将其改为使用命名字段的结构。

// this seemed fine at first...
struct OldRgbColor(u8, u8, u8);

// ...but ultimately `color.r` reads better than `color.0`
struct NewRgbColor {
    r: u8,
    g: u8,
    b: u8,
}

如果不确定该如何处理，我们建议使用带有名称字段的结构体。

单元式结构


第三种结构类型声明了一个没有任何字段的类型：

/// An error type indicating that the server is on fire.
/// No fields -- when this occurs, there's not much to say.
struct ServerOnFireError;


这种类型的数值并不占用任何内存空间，就像单位类型 () 一样。Rust 并不会实际在内存中存储类似单位类型的结构体值，也不会生成用于操作这些值的代码。但从逻辑上讲，一个空结构体本质上也是一种类型，可以像其他类型一样拥有值——或者更准确地说，它只包含一个值。

let err = ServerOnFireError;

这类似于在没有定义任何字段的情况下声明一个命名字段结构：

struct NoFields {}
let n = NoFields {};


在阅读《Fields and Elements》中关于 .. 范围运算符的内容时，你已经遇到过一个类似结构的对象。而像 3..5 这样的表达式，实际上是结构体值 Range { start: 3, end: 5 } 的简写形式；至于 .. 这种仅包含范围元素的表达式，则是对类似结构值 RangeFull 的简写形式。

结构布局


在内存中，无论是命名字段结构还是元组结构，本质上都是同一种东西：一系列的值，这些值的类型可以混合，并且以特定的方式存储在内存中。例如，在本章的早期部分，我们定义了这个结构：

struct GrayscaleMap {
    pixels: Vec<u8>,
    size: (usize, usize),
}


在内存中， GrayscaleMap 值被存储如图 9-1 所示。

与 C 语言和 C++不同，Rust 并没有对结构体中字段在内存中的排序方式做出明确的规定；这张图仅展示了一种可能的排列方式。不过，Rust 确实承诺将字段的值直接存储在结构体的内存块中。而 JavaScript、Python 和 Java 则会将 pixels 和 size 的值分别存储在各自的堆分配的内存块中，并且让 GrayscaleMap 的字段指向这些内存块。而 Rust 则直接将 pixels 和 size 的值嵌入到 GrayscaleMap 的值中。只有由 pixels 向量所拥有的堆分配内存块仍然保持独立的状态。


你可以要求 Rust 以与 C 和 C++兼容的方式来布局结构体，可以使用 #[repr(C)] 属性来实现这一点。我们将在第 24 章中详细讨论这一点。

使用`impl`定义方法


在整本书中，我们一直都在对各种值调用方法。我们使用 v.push(e) 将元素添加到向量中，使用 v.len() 获取它们的长度，使用 r.expect("msg") 检查 Result 值是否有错误，等等。你也可以在自己的结构体类型上定义方法。与 C++或 Java 不同，Rust 中的方法出现在单独的 impl 块中，而不是在结构体定义内部。

/// A first-in, first-out queue of characters.
pub struct Queue {
    older: Vec<char>,    // older elements, eldest last.
    younger: Vec<char>,  // younger elements, youngest last.
}

impl Queue {
    /// Pushes a character onto the back of a queue.
    pub fn push_back(&mut self, c: char) {
        self.younger.push(c);
    }

    /// Pops a character off the front of a queue. Returns `Some(c)` if there
    /// was a character to pop, or `None` if the queue was empty.
    pub fn pop_front(&mut self) -> Option<char> {
        if self.older.is_empty() {
            if self.younger.is_empty() {
                return None;
            }

            // Bring the elements in younger over to older, and put them in
            // the promised order.
            std::mem::swap(&mut self.older, &mut self.younger);
            self.older.reverse();
        }

        // Now older is guaranteed to have something. Vec's pop method
        // already returns an Option, so we're set.
        self.older.pop()
    }
}


在 impl 块中定义的函数被称为关联函数，因为它们与某种特定的类型相关联。而在其他位置定义的函数则有时被称为自由函数——即那些没有固定关联的函数。


那些带有 self 参数的相关函数被称为方法。而没有 self 参数的相关函数则类似于其他语言中的静态方法或构造函数；我们将在接下来的几页中详细介绍这些内容。

在我们的例子中， push_back 和 pop_front 方法分别指向 Queue 对象的 self.older 和 self.younger 字段。与 C++和 Java 不同，在 C++和 Java 中，“this”对象的成员可以在方法体中以未限定的标识符来访问。而 Rust 中，方法必须明确使用 self 来引用其调用所依赖的值，这一点类似于 Python 中方法使用 self 的方式，而 JavaScript 中方法则使用 this 来表示引用。

由于 push_back 和 pop_front 都需要修改 Queue ，所以它们都使用了 &mut self 作为参数。不过，当调用一个方法时，你不需要自己手动创建可变的引用；普通的方法调用语法已经自动处理了这一点。因此，有了这些定义之后，你就可以这样使用 Queue 了：

let mut q = Queue {
    older: Vec::new(),
    younger: Vec::new(),
};

q.push_back('0');
q.push_back('1');
assert_eq!(q.pop_front(), Some('0'));

q.push_back('∞');
assert_eq!(q.pop_front(), Some('1'));
assert_eq!(q.pop_front(), Some('∞'));
assert_eq!(q.pop_front(), None);

仅仅通过编写 q.push_back(...) ，就可以获得对 q 的可变引用，就像你编写了 (&mut q).push_back(...) 一样，因为 push_back 方法的 self 正是需要这个引用来执行的。

如果某个方法不需要修改其 self ，那么你可以定义它接受共享引用。例如：

impl Queue {
    pub fn is_empty(&self) -> bool {
        self.older.is_empty() && self.younger.is_empty()
    }
}

同样，方法调用表达式能够确定需要借用的是哪种类型的引用：

assert!(q.is_empty());
q.push_back('☉');
assert!(!q.is_empty());

或者，如果某个方法想要获取 self 的所有权，它可以通过值传递的方式接收 self ：

impl Queue {
    pub fn split(self) -> (Vec<char>, Vec<char>) {
        (self.older, self.younger)
    }
}

调用这个 split 方法的方式与其他方法调用类似：

let (older, younger) = q.split();


但是请注意，由于 split 以值的形式接收了 self ，这就使得 Queue 不再属于 q 了，因此 q 也无法再被使用了。而由于 split 的 self 现在拥有队列的所有权，因此它可以将那些单独的向量从队列中移除，并将其返回给调用者。

将自我视为一个盒子、一个半径或弧线


一个方法的 self 参数也可以是一个 Box<Self> 、 Rc<Self> 或 Arc<Self> 类型。这样的方法只能作用于该指针类型的对象上。调用该方法时会将指针的所有权传递给调用者。

let mut bq = Box::new(Queue::new());

// `Queue::push_back` expects a `&mut Queue`, but `bq` is a `Box<Queue>`.
// This is fine: Rust borrows a `&mut Queue` from the `Box` for the
// duration of the call.
bq.push_back('■');

在方法调用和字段访问时，Rust 会自动从指针类型中借用引用，比如 Box 、 Rc 和 Arc 。因此，在方法签名中， &self 和 &mut self 几乎总是合适的选择，偶尔也会使用 self 。


不过，如果真的存在某种方法需要拥有一个指向 Self 的指针，而它的调用者手头有这样一个指针，那么 Rust 允许你将 Self 作为该方法的 self 参数传递。为此，你必须明确指定 self 的类型，就像它是一个普通的参数一样。

impl OrbitComputeJob {
    /// Adds this job to the application-wide list of active jobs, so that
    /// we'll wait for it to finish on shutdown.
    fn mark_active(self: &Arc<Self>) {
        let new_ref = Arc::clone(self); // bump reference count
        App::add_active_job(new_ref);
    }
}

非方法相关函数


impl 块还可以定义一些不接受 self 参数的相关函数。这些函数通常用于提供构造函数，如下所示：

impl Queue {
    pub fn new() -> Queue {
        Queue {
            older: Vec::new(),
            younger: Vec::new(),
        }
    }
}

这就定义了相关的函数 Queue::new 。现在，我们的示例代码变得更加简洁了：

let mut q = Queue::new();

q.push_back('*');
...

在 Rust 语言中，传统的做法是将构造函数命名为 new 形式。我们已经见过 Vec::new 、 Box::new 、 HashMap::new 等类似的命名方式。不过， new 这个命名并没有什么特别之处。它并不是一个关键字，而且通常类型会有一些其他的相关函数作为构造函数，比如 Vec::with_capacity 。


虽然你可以为同一种类型创建多个独立的 impl 块，但这些块必须都位于定义该类型的同一个包中。不过，Rust 允许你为其他类型添加自己的方法；我们将在第 11 章中详细介绍这一点。

  • 在 C++中，找到某个类型的数据成员通常很简单。而在大型的 C++类定义中，你可能需要浏览数百行成员函数定义，以确保没有遗漏任何数据成员。而在 Rust 中，所有数据成员都集中在一个地方。


  • 虽然可以将方法嵌入到带有命名字段的结构体的语法中，但对于元组や类似单元的结构体来说则不太方便。将方法提取到 impl 块中后，就可以为这三种结构体使用统一的语法了。实际上，Rust 在定义非结构体类型的类型上的方法时，也使用了同样的语法，比如 enum 类型以及 i32 这样的基本类型。 (任何类型都可以拥有方法，这一点就是 Rust 不常使用“对象”这个术语的原因，因为它更愿意将所有元素都称为“值”。)


  • 同样的 impl 语法也适用于实现特质，我们将在第十一章中详细讨论这一点。

相关常数


像 C#和 Java 这样的语言在类型系统中有一个特点，Rust 也采用了这一机制：即值是与某个类型相关联的，而不是与该类型的某个具体实例相关联。在 Rust 中，这种特性被称为“关联常量”。

pub struct Vector2 {
    x: f32,
    y: f32,
}

impl Vector2 {
    const ZERO: Vector2 = Vector2 { x: 0.0, y: 0.0 };
    const UNIT: Vector2 = Vector2 { x: 1.0, y: 0.0 };
}

这些值是与类型本身相关的，因此无需引用 Vector2 的另一个实例即可使用它们。就像相关函数一样，可以通过指定与类型相关联的类型，然后加上该类型的名称来访问这些值。

let scaled = Vector2::UNIT.scaled_by(2.0);

而且，关联常量也不必与它所关联的类型具有相同的类型；我们可以利用这一特性为类型添加编号或名称。例如，如果有多个类似于 Vector2 的类型需要写入文件，然后再加载到内存中，那么就可以使用关联常量来为这些类型添加名称或数字编号，从而将这些信息标注在数据旁边以标识其类型。

impl Vector2 {
    const NAME: &'static str = "Vector2";
    const ID: u32 = 18;
}

通用结构体


我们对 Queue 的定义并不满意：虽然这个结构体被设计用来存储字符，但它的结构或方法并没有针对字符特性进行特殊设计。如果我们再定义一个结构体，用来存储比如 String 这样的数值，那么代码看起来还是一样的，只不过 char 会被替换为 String 。但这显然是一种浪费时间的行为。


幸运的是，Rust 中的结构体可以是通用的，也就是说，它们的定义只是一个模板，你可以将任何你喜欢的类型插入到这个模板中。例如，下面这个定义就是用于定义 Queue 的，它可以容纳任何类型的数值：

pub struct Queue<T> {
    older: Vec<T>,
    younger: Vec<T>,
}

你可以在 Queue<T> 中看到 <T> 被定义为“对于任何类型 T ……的元素类型”。所以，这个定义的意思是：“对于任何类型 T ，一个 Queue<T> 由两个类型为 Vec<T> 的字段组成”。例如，在 Queue<String> 中， T 是 String ，因此 older 和 younger 的类型是 Vec<String> 。在 Queue<char> 中， T 是 char ，我们得到了一个与 char 特定定义相同的结构体。实际上， Vec 本身就是一个通用结构体，就是以这种方式定义的。


在通用结构体定义中，位于 < 尖括号 > 内的类型名称被称为类型参数。一个通用结构体的定义块如下所示： impl 

impl<T> Queue<T> {
    pub fn new() -> Queue<T> {
        Queue {
            older: Vec::new(),
            younger: Vec::new(),
        }
    }

    pub fn push_back(&mut self, t: T) {
        self.younger.push(t);
    }

    pub fn is_empty(&self) -> bool {
        self.older.is_empty() && self.younger.is_empty()
    }

    ...
}

你可以将字符串 impl<T> Queue<T> 翻译为类似“对于任何类型 T ，这里有一些与 Queue<T> 相关的函数”这样的表述。然后，你可以将类型参数 T 作为相关函数定义中的类型使用。

这种语法结构看起来有些冗余，但是 impl<T> 这个符号明确表示 impl 这个代码块可以涵盖任何类型的 T ，这与那些只是为了某种特定类型的 Queue 而编写的 impl 代码块有所区别。就像这样：

impl Queue<f64> {
    fn sum(&self) -> f64 {
        ...
    }
}

这个 impl 块头信息写道：“这里有一些专门针对 Queue<f64> 的功能。”这意味着 Queue<f64> 可以使用 sum 方法，而其它类型的 Queue 则无法使用这种方法。


每一个 impl 块，无论是通用的还是特殊的，都会定义一种特殊类型参数 Self （注意其名称为 CamelCase ），该参数代表我们为其添加方法的类型。在上面的代码中， Self 实际上就是 Queue<T> ，因此我们可以进一步简写 Queue::new 的定义为：

pub fn new() -> Self {
    Queue {
        older: Vec::new(),
        younger: Vec::new(),
    }
}

你可能已经注意到，在 new 中，我们不需要在构造表达式中写明类型参数；仅仅编写 Queue { ... } 就足够了。这就是 Rust 中的类型推断功能：由于该函数的返回值只对应一种类型——即 Queue<T> ——因此 Rust 会自动为参数提供相应的类型。不过，在函数签名和类型定义中，你仍然需要明确指定类型参数。Rust 不会自动推断这些类型；而是会将这些显式的类型作为基础，从而在函数体内进行类型推断。

Self 也可以以这种方式使用；我们完全可以写成 Self { ... } 。选择哪种表达方式取决于你认为哪种更容易理解。

对于相关的函数调用，可以使用 ::<> （Turbofish）符号来明确指定类型参数：

let mut q = Queue::<char>::new();

但实际上，通常你可以让 Rust 自行处理这些事情：

let mut q = Queue::new();
let mut r = Queue::new();

q.push_back("Marrakesh");  // apparently a Queue<&str>
r.push_back(6798.383);     // apparently a Queue<f64>


实际上，这正是我们在书中对 Vec 这种通用结构体类型所进行的操作。

具有生命周期参数的通用结构体


正如我们在“包含引用的结构体”一文中讨论过的那样，如果一个结构体类型包含了引用，那么就必须为这些引用指定生命周期。例如，这里有一个结构体，它可能包含对某个切片中最大值和最小值的引用：

struct Extrema<'elt> {
    greatest: &'elt i32,
    least: &'elt i32,
}


之前，我们邀请您思考一个这样的声明： struct Queue<T> 。它的含义是，对于任何特定的类型 T ，都可以创建一个 Queue<T> ，该 Queue<T> 能够持有该类型。同样地，您也可以将 struct Extrema<'elt> 理解为：对于任何特定的生命周期 'elt ，都可以创建一个 Extrema<'elt> ，该 Extrema<'elt> 能够持有对该生命周期的引用。

fn find_extrema<'s>(slice: &'s [i32]) -> Extrema<'s> {
    let mut greatest = &slice[0];
    let mut least = &slice[0];

    for i in 1..slice.len() {
        if slice[i] < *least    { least    = &slice[i]; }
        if slice[i] > *greatest { greatest = &slice[i]; }
    }
    Extrema { greatest, least }
}


在这里，由于 find_extrema 使用了 slice 的某些元素，而 slice 的生命周期为 's ，因此我们返回的 Extrema 结构体的引用也使用了 's 作为其生命周期。Rust 会自动推断调用的生命周期参数，所以对 find_extrema 的调用无需特别说明这些参数。

let a = [0, -3, 0, 15, 48];
let e = find_extrema(&a);
assert_eq!(*e.least, -3);
assert_eq!(*e.greatest, 48);

因为返回类型的生命周期通常与参数的生命周期相同，所以 Rust 允许我们通过省略生命周期参数来缩写函数签名。我们可以这样写函数签名： find_extrema ’s，而意思并没有改变。

fn find_extrema(slice: &[i32]) -> Extrema<'_> {
    ...
}


Rust 编译器注意到 slice 这个参数是一个引用，因此推断出这个函数的参数具有未明确规定的生命周期。在返回类型 Extrema<'_> 中，占位符生命周期 '_ 指的是这个隐式的生命周期。

不过，对于那些具有多个参数且每个参数都带有生命周期的函数来说，Rust 通常不会自动推断返回类型中的生命周期信息，因此你必须手动明确说明所有相关的内容。

具有常量参数的通用结构体

一个通用的结构体也可以接受常量参数。例如，你可以这样定义一个表示任意阶多项式的类型：

/// A polynomial of degree N - 1.
struct Polynomial<const N: usize> {
    /// The coefficients of the polynomial.
    ///
    /// For a polynomial a + bx + cx² + ... + zxⁿ⁻¹,
    /// the `i`'th element is the coefficient of xⁱ.
    coefficients: [f64; N],
}

根据这一定义，例如， Polynomial<3> 就是一个二次多项式。 <const N: usize> 子句指出， Polynomial 类型需要一个 usize 类型的参数作为通用参数，该参数用于决定需要存储多少个系数。


与 Vec 不同， Vec 的字段存储了长度和数据容量信息，并且元素存储在堆中。而 Polynomial 则将系数直接存储在数值本身中，不需要其他存储结构。长度由类型决定。（因为 Polynomial 无法动态扩展，所以不需要考虑容量问题。）

impl<const N: usize> Polynomial<N> {
    fn new(coefficients: [f64; N]) -> Polynomial<N> {
        Polynomial { coefficients }
    }

    /// Evaluates the polynomial at `x`.
    fn eval(&self, x: f64) -> f64 {
        // Horner's method is numerically stable, efficient, and simple:
        // c₀ + x(c₁ + x(c₂ + x(c₃ + ... x(c[n-1] + x c[n]))))
        let mut sum = 0.0;
        for i in (0..N).rev() {
            sum = self.coefficients[i] + x * sum;
        }

        sum
    }
}


在这里， new 函数接受一个长度为 N 的数组，并将该数组中的元素作为新的 Polynomial 值的系数。 eval 方法会遍历从 0..N 到 x 的范围，以计算多项式在给定点 x 处的值。

use std::f64::consts::FRAC_PI_2;   // π/2

// Approximate the `sin` function: sin x ≅ x - 1/6 x³ + 1/120 x⁵
// Around zero, it's pretty accurate!
let sine_poly = Polynomial::new([0.0, 1.0, 0.0, -1.0/6.0, 0.0, 1.0/120.0]);
assert_eq!(sine_poly.eval(0.0), 0.0);
assert!((sine_poly.eval(FRAC_PI_2) - 1.).abs() < 0.005);


由于我们传递了一个包含六个元素的数组，因此 Rust 知道我们需要构造一个 Polynomial<6> 对象。 eval 方法通过查看其 Self 类型，就能知道 for 循环应该执行多少次迭代。由于数组的长度在编译时就已经确定，编译器很可能会完全用直线型代码来替代原来的循环结构。


const 类型的泛型参数可以是任何整数类型，例如 char 或 bool 。不允许使用浮点数、枚举类型以及其他类型。

struct LumpOfReferences<'a, T, const N: usize> {
    the_lump: [&'a T; N],
}

常量泛型参数在 Rust 语言中是一个相对较新的特性，目前它们的使用受到了一定的限制。例如，更合理的做法是将 Polynomial 定义为这样：

/// A polynomial of degree N.
struct Polynomial<const N: usize> {
    coefficients: [f64; N + 1],
}

然而，Rust 并不认同这种定义：

error: generic parameters may not be used in const operations
  |
6 |     coefficients: [f64; N + 1]
  |                         ^ cannot perform const operation using `N`
  |
  = help: const parameters may only be used as standalone arguments
          here, i.e. `N`

虽然使用 [f64; N] 这种表示法没有问题，但像 [f64; N + 1] 这样的类型在 Rust 语言中似乎显得过于大胆了。不过，Rust 目前采用了这种限制措施，以避免出现类似的问题。

struct Ketchup<const N: usize> {
    tomayto: [i32; N & !31],
    tomahto: [i32; N - (N % 32)],
}


事实证明，对于所有 N 的值来说， N & !31 和 N - (N % 32) 都是相等的，因此 tomayto 和 tomahto 始终具有相同的类型。例如，应该允许将其中一个类型赋值给另一个类型。但是，如果让 Rust 的类型检查器了解这种复杂的代数运算，可能会引入一些令人困惑的特殊情况，而这一特性本身就已经相当复杂了。当然，像 N + 1 这样的简单表达式则表现得更加合理，目前已经有相关工作正在努力让 Rust 能够正确处理这类情况。


由于这里关注的是类型检查器的行为，因此这一限制仅适用于出现在类型中的常量参数，比如数组的长度。在普通的表达式中，你可以随意使用 N ，而 N + 1 和 N & !31 也是完全可行的。


如果您想为 const 通用参数提供的值不是一个简单的字面量或标识符，那么您必须将其包裹在括号中，就像 Polynomial<{5 + 1}> 那样。这条规则能让 Rust 更精确地检测出语法错误。

为结构类型推导共同特性


这些结构其实很容易编写：

struct Point {
    x: f64,
    y: f64,
}

不过，如果你开始使用这种 Point 类型的话，你会很快发现它有一些不便之处。按照当前的写法， Point 是无法被复制或克隆的。你无法使用 println!("{point:?}"); 来打印它，而且它也不支持 == 和 != 这些运算符。


这些特性在 Rust 中都有各自的名称—— Copy 、 Clone 、 Debug 和 PartialEq 。它们被称为“特质”。在第十一章中，我们将介绍如何手动为自己的结构体实现这些特质。不过，对于这些标准特质以及其他一些特质来说，除非你需要某种特殊的行为，否则无需手动实现它们。Rust 可以自动为你实现这些特质，而且非常精确。只需在结构体上添加 #[derive] 属性即可。

#[derive(Copy, Clone, Debug, PartialEq)]
struct Point {
    x: f64,
    y: f64,
}


这些特质都可以自动应用于结构体，只要每个字段都实现了相应的特质即可。对于 Point 来说，我们可以让 Rust 自动为它派生出 PartialEq 这个特质，因为 Point 的两个字段都是 f64 类型的，而 f64 已经实现了 PartialEq 这个特质。


我们将在第十三章中详细介绍 Rust 的标准特性，并说明哪些特性是可行的。

内部可变性


可变性就像芥末一样：使用过量时会导致问题，但通常我们只需要一点点即可。例如，假设你的蜘蛛机器人控制系统有一个中央结构 SpiderRobot ，里面包含了各种设置和输入接口。这个结构在机器人启动时会自动加载，而且数值不会发生变化。

pub struct SpiderRobot {
    species: String,
    web_enabled: bool,
    leg_devices: [OwnedFd; 8],
    ...
}

机器人的每个主要系统都由不同的结构来处理，而每个结构都包含一个指向 SpiderRobot 的指针。

use std::rc::Rc;

pub struct SpiderSenses {
    robot: Rc<SpiderRobot>,  // <-- pointer to settings and I/O
    eyes: [Camera; 32],
    motion: Accelerometer,
    ...
}


用于网络构建、捕食行为、毒液流动控制等功能的结构体，也都包含了一个 Rc<SpiderRobot> 智能指针。需要注意的是， Rc 表示引用计数，而 Rc 框中的值总是共享的，因此永远不可更改。


这种情况经常会发生。我们需要的是在那些本质上不可变的值（如 SpiderRobot 结构）内部，添加一些可变的数据（如 File ）。这种特性被称为“内部可变性”。Rust 提供了多种实现方式；在本节中，我们将讨论两种最简单的实现方式： Cell<T> 和 RefCell<T> ，这两种实现都在 std::cell 模块中。


Cell<T> 是一个结构体，其中包含一个类型为 T 的私有字段。 Cell 这个结构体的特殊之处在于，即使你没有 mut 的访问权限，仍然可以获取和设置这个字段的值。

Cell::new(value)

创建一个新的 Cell ，并将给定的 value 移动到该新对象中。

cell.get()

返回 cell 中值的副本。

cell.set(value)

将给出的 value 值存储在 cell 中，同时会丢弃之前已存储的值。

这种方法的参数是 self ，而 mut 并不是一个有效的参考值。

fn set(&self, value: T)    // note: not `&mut self`


当然，对于名为 set 的方法来说，这种情况并不常见。到目前为止，Rust 已经让我们习惯了这种想法：如果我们想要对数据进行修改，就需要使用 mut 权限。不过，同样地，这种不寻常的细节正是 Cell 方法的精髓所在。它们只不过是一种安全的方式来打破不可变性的规则罢了——仅此而已。


细胞还拥有一些其他的方法，你可以在相关文档中了解到这些方法的详细信息。

use std::cell::Cell;

pub struct SpiderRobot {
    ...
    hardware_error_count: Cell<u32>,
    ...
}

那么，即使是 SpiderRobot 中那些非 mut 的方法，也可以使用 .get() 和 .set() 方法来访问那个 u32 。

impl SpiderRobot {
    /// Increases the error count by 1.
    pub fn add_hardware_error(&self) {
        let n = self.hardware_error_count.get();
        self.hardware_error_count.set(n + 1);
    }

    /// True if any hardware errors have been reported.
    pub fn has_hardware_errors(&self) -> bool {
        self.hardware_error_count.get() > 0
    }
}


这其实很简单，但并不能解决我们的日志记录问题。 Cell 不允许你调用 mut 中的方法来处理共享值。 .get() 方法会返回单元格中值的副本，因此只有当 T 实现了 Copy 特性时，这个方法才有效。对于日志记录来说，我们需要一个可修改的 File ，而 File 是不可复制的。


在这种情况下，合适的工具就是 RefCell 。就像 Cell<T> 一样， RefCell<T> 也是一种通用类型，它只包含一个 T 类型的值。与 Cell 不同， RefCell 支持借用对其 T 值的引用。

RefCell::new(value)


创建一个新的 RefCell ，将 value 移入其中。

ref_cell.borrow()


返回 Ref<T> 的值，实际上就是一个对存储在 ref_cell 中的值的共享引用。

ref_cell.borrow_mut()


返回 RefMut<T> 的值，实际上是一个对 ref_cell 中值的可修改的引用。

ref_cell.try_borrow(), ref_cell.try_borrow_mut()


他们的操作方式与 borrow() 和 borrow_mut() 类似，但返回的是一个 Result 类型的值。如果值已经是可修改的“借用状态”，他们不会引发恐慌，而是返回一个 Err 类型的值。


另外， RefCell 还有一些其他方法，你可以在相关文档中找到这些信息。


这两种方法只有在你违反 Rust 中的规则时才会引发恐慌，即 mut 的引用必须是独占引用。例如，以下这种情况会引发恐慌：

use std::cell::RefCell;

let ref_cell: RefCell<String> = RefCell::new("hello".to_string());

let r = ref_cell.borrow();      // ok, returns a Ref<String>
let count = r.len();            // ok, returns "hello".len()
assert_eq!(count, 5);

let mut w = ref_cell.borrow_mut();  // panic: already borrowed
w.push_str(" world");

为了避免陷入恐慌，你可以将这两笔借款分配到不同的账户中。这样，在尝试借款 w 之前， r 这笔款项就会先被处理掉。


这其实和常规引用机制的工作原理非常相似。唯一的区别在于，通常情况下，当你引用某个变量时，Rust 会在编译阶段进行检查，以确保你能够安全地使用该引用。如果检查失败，就会引发编译错误。而 RefCell 则采用运行时检查来强制执行同样的规则。因此，如果你违反了这些规则，就会引发 panic 错误（或者触发 Err 、 try_borrow 和 try_borrow_mut 中的相应处理）。

pub struct SpiderRobot {
    ...
    log_file: RefCell<File>,
    ...
}

impl SpiderRobot {
    /// Writes a line to the log file.
    pub fn log(&self, message: &str) {
        let mut file = self.log_file.borrow_mut();
        // `writeln!` is like `println!`, but sends
        // output to the given file.
        writeln!(file, "{message}").unwrap();
    }
}


变量 file 的类型为 RefMut<File> 。它可以像可变的引用一样被使用，指向 File 对象。关于如何向文件中写入数据的详细信息，请参见第 18 章。


细胞非常易于使用。虽然需要调用 .get() 、 .set() 或 .borrow() 、 .borrow_mut() 会有些麻烦，但这正是打破常规规则的代价。另一个缺点则不太明显，但更为严重：细胞以及包含它们的任何类型都不是线程安全的。因此，Rust 不允许多个线程同时访问它们。我们将在第十九章中讨论线程安全的内部可变性机制，届时我们会介绍“Mutex”、“Atomics”以及“全局变量”等相关内容。


无论是结构体具有命名字段，还是属于元组结构，它们本质上都是对其他值的聚合。例如，如果我有一个 SpiderSenses 结构体，那么我就有了一个指向共享 SpiderRobot 结构体的 Rc 指针。此外，我还拥有眼睛、加速度计等等。Rust 还支持一种类型，它能够从多个可能的类型中选择其中一个。这种类型非常实用，因此在语言中随处可见，它们将是下一章的主题。
