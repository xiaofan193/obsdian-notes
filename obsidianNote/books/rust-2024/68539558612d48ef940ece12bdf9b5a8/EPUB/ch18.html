黑暗之星

输入和输出是将程序中的抽象逻辑转化为可实际作用于现实世界的过程的组成部分。通常情况下，这意味着需要处理文件系统和网络接口相关的工作；不过，也存在一些更为特殊类型的输入输出方式。

正如 Rust 的标准库通常所追求的那样，它让简单的任务变得如此简单。读取一个采用 UTF-8 编码的文本文件（或者 HTML 文档、CSV 文件等）就像调用 std::fs::read_to_string 这样的函数一样简单。

let contents = std::fs::read_to_string("file.txt")
    .expect("Unable to read file");

这类便捷的功能使得编写大量程序变得容易，但它们都是基于两个相对简单的输入/输出特性而构建的： Read 和 Write 。在本章中，我们将演示如何利用这些特性来读写文件，以及如何与文件系统、终端和网络进行交互。

读者与作家


“读者”是您的程序可以读取字节数据的对象。它们实现了 std::io::Read 特性。例如：

  • 使用 std::fs::File::open(filename) 打开的文件

  • std::net::TcpStream s，用于通过网络接收数据

  • std::io::stdin() ，用于从进程的标准输入流中读取数据


  • std::io::Cursor<&[u8]> 和 std::io::Cursor<Vec<u8>> 这些值指的是那些从已存储在内存中的字节数组或向量中“读取”数据的读取器。


“Writer”是指你的程序可以向其写入字节的数据对象。它们实现了 std::io::Write 特性。例如：

  • 使用 std::fs::File::create(filename) 打开的文件

  • std::net::TcpStream s，用于在网络上传输数据

  • std::io::stdout() 和 std::io:stderr() ，用于向终端输出文本

  • Vec<u8> ，一位在 write 方法上添加了追加操作的作家

  • std::io::Cursor<Vec<u8>> ，它与之类似，但允许进行数据的读写操作，并且可以在向量内的不同位置进行寻址。


  • std::io::Cursor<&mut [u8]> ，它和 std::io::Cursor<Vec<u8>> 非常相似，不过它无法扩展缓冲区的大小，因为它只是对现有字节数组的一部分进行了切片而已。


由于 Read 和 Write 这些特性属于标准库的一部分，因此它们被广泛应用于整个 Rust 生态系统中。因此，编写能够在各种输入或输出环境中运行的通用代码是很常见的。例如，下面这个函数可以将任何读取器中的字节数据复制到任何写入器中：

use std::io::{self, ErrorKind, Read, Write};

const DEFAULT_BUF_SIZE: usize = 8 * 1024;

pub fn copy<R, W>(reader: &mut R, writer: &mut W) -> io::Result<u64>
where
    R: Read + ?Sized,
    W: Write + ?Sized,
{
    let mut buf = [0; DEFAULT_BUF_SIZE];
    let mut written = 0;
    loop {
        let len = match reader.read(&mut buf) {
            Ok(0) => return Ok(written),
            Ok(len) => len,
            Err(ref e) if e.kind() == ErrorKind::Interrupted => continue,
            Err(e) => return Err(e),
        };
        writer.write_all(&buf[..len])?;
        written += len as u64;
    }
}


这是从 Rust 标准库中的 std::io::copy() 函数简化后的实现。由于它是通用的，因此你可以用它来将数据从 File 复制到 TcpStream ，从 Stdin 复制到内存中的 Vec<u8> 等。


如果这里的错误处理代码不清楚，请参考第 7 章。在接下来的章节中，我们会频繁使用 Result 这种类型；理解其工作原理非常重要。


std::io 中的 Read 和 Write 特性，以及 BufRead 和 Seek 特性，被广泛使用，以至于甚至有一个名为 prelude 的模块，里面只包含了这些特性。

use std::io::prelude::*;


在这一章中，你会看到这一块内容一两次。我们还养成了导入 std::io 模块的习惯：

use std::io::{self, ErrorKind, Read, Write};

这里的 self 关键字将 io 定义为 std::io 模块的别名。这样， std::io::Result 和 std::io::Error 就可以更简洁地写作 io::Result 和 io::Error 等形式。

读者们


std::io::Read 有多种数据读取方法。所有这些方法都通过 mut 引用来指向读取器本身。

reader.read(&mut buffer)


从数据源中读取了一些字节数据，并将其存储在指定的 buffer 中。 buffer 参数的类型即为 &mut [u8] 。这一操作共读取了最多 buffer.len() 字节的数据。


返回类型为 io::Result<u64> ，这是 Result<u64, io::Error> 的别名。当操作成功时， u64 的值表示读取的字节数——这个数值可能等于或小于 buffer.len() 的值。不过，如果数据源还有更多数据需要读取，那么 u64 的值仍然可能大于 buffer.len() 的值。而 Ok(0) 则表示没有更多的数据需要读取。

在出现错误时， .read() 会返回 io::Error 这个值。这种错误类型有一个 .kind() 方法，该方法会返回一种类型为 io::ErrorKind 的错误代码；同时，该错误类型还包含一个枚举，其中包含诸如 PermissionDenied 和 ConnectionReset 这样的成员。大多数错误都是无法忽视的严重问题，但有一种错误需要特别处理。 io::ErrorKind::Interrupted 对应于 Unix 错误代码 EINTR ，这意味着读取操作被某种信号中断了。除非程序能够巧妙地处理这些信号，否则应该重新尝试读取操作。前面章节中的 copy() 代码就展示了一个这样的例子。

如你所见， .read() 方法的使用门槛非常高，甚至还会继承底层操作系统的某些特性。如果你需要为某种新的数据源实现 Read 特性，那么这种方式会给你带来很大的灵活性。不过，如果尝试读取某些数据的话，就会变得很麻烦了。因此，Rust 提供了一些更高级的便捷方法。所有这些方法都拥有 .read() 的默认实现，它们可以处理 ErrorKind::Interrupted 的情况，所以你无需自己动手编写代码。

reader.read_to_end(&mut byte_vec)


读取该读取器中的所有剩余输入，将它们追加到 byte_vec 中，而 byte_vec 是一个 Vec<u8> 。最终返回一个 io::Result<usize> ，表示读取的字节数。

这种方法可以无限地增加向量中的数据量，因此不要将其用于不可信的源数据。（你可以使用 .take() 方法来限制数据量，具体方法将在下文中描述。）

reader.read_to_string(&mut string)


情况是一样的，只不过会将给定的数据追加到指定的 String 中。如果流不是有效的 UTF-8 编码，则会返回 ErrorKind::InvalidData 错误。

在某些编程语言中，字节输入和字符输入是由不同类型的类型来处理的。如今，UTF-8 已经成为主流标准，Rust 语言也认可了这一事实上的标准，并在所有地方都支持 UTF-8 编码。其他字符集也可以通过开源的 encoding crate 框架来支持。

reader.read_exact(&mut buf)


读取的数据量刚好足以填充给定的缓冲区。该参数的类型為 &[u8] 。如果读取器在读取 buf.len() 字节之前就耗尽了数据，则会返回 ErrorKind::UnexpectedEof 错误。

这些是 Read trait 的主要使用方法。此外，还有三种适配器方法可以接受 reader 参数，并将其转换为迭代器或其他读取器形式：

reader.bytes()


该接口返回一个用于遍历输入流中每个字节的迭代器。该接口的数据类型為 io::Result<u8> ，因此对于每个字节都需要进行错误检查。此外，该接口每处理一个字节就会调用一次 reader.read() 函数，如果未对数据进行缓冲的话，这将会非常低效。

reader.chain(reader2)


返回一个新的读取器，它首先读取来自 reader 的所有输入数据，然后读取来自 reader2 的所有输入数据。

reader.take(n)


返回一个新的读取器，它从与 reader 相同的源读取数据，但只能处理最多 n 字节的数据。


没有专门用于关闭读取器的方法。通常，读取器和写入器都会采用 Drop 这样的实现方式，从而能够自动关闭它们。

缓冲读取器


为了提升效率，可以引入缓冲机制来处理读写操作。也就是说，会有一块内存作为缓冲区，用来存储输入或输出数据。这样就能减少系统调用的次数，如图 18-1 所示。在示例中，应用程序通过调用 .read_line() 方法从 BufReader 处读取数据；而 BufReader 则从操作系统处获取更大规模的数据输入。

这张图并非按比例绘制的。实际上， BufReader 的缓冲区默认大小有数千字节；因此，单个系统 read 可以处理数百个 .read_line() 调用。这一点很重要，因为系统调用过程非常缓慢。

（如图片所示，操作系统也有缓冲区，原因相同：系统调用的速度较慢，而读取磁盘数据的过程同样比较缓慢。）

缓冲读取器实现了 BufReadRead 功能，同时还具备另一个特性 ，该特性包含了以下方法：

reader.read_line(&mut line)


读取一行文本并将其附加到 line 中。这行文本的换行符 '\n' 也会被包含在 line 中。如果输入文件的行结束符是 Windows 风格的，那么 "\r\n" 和 line 中的字符都会被包含进来。

返回值为一个 io::Result<usize> ，表示读取的字节数，包括行结束符（如果有的话）。

如果读者已经到达输入的末尾，那么 line 将保持不变，返回 Ok(0) 。

reader.lines()


该工具返回一个用于遍历输入行内容的迭代器。其返回值类型为 io::Result<String> 。换行符不会被包含在字符串中。如果输入文件的行结束符采用 Windows 风格，那么这两个字符都会被去除。

这种方法几乎总是适合用于文本输入。接下来的两部分将展示一些该方法的应用实例。

reader.read_until(stop_byte, &mut byte_vec), reader.split(stop​_byte)


这些其实和 .read_line() 以及 .lines() 类似，但是是以字节为单位进行操作的。它们会生成 Vec<u8> 而不是 String 。你可以选择使用 stop_byte 作为分隔符。


BufRead 还提供了一对低级方法， .fill_buf() 和 .consume(n) ，可以直接访问读者的内部缓冲区。有关这些方法的更多信息，请参阅在线文档。

接下来的两部分将更详细地介绍缓冲读取器的工作原理。

阅读语句


这是一个实现了 Unix 中的 grep 功能的函数。它会在许多文本行中搜索给定的字符串，这些文本行通常是从另一个命令中传递来的。

use std::io;
use std::io::prelude::*;

fn grep(target: &str) -> io::Result<()> {
    for line_result in io::stdin().lines() {
        let line = line_result?;
        if line.contains(target) {
            println!("{line}");
        }
    }
    Ok(())
}

这个函数的功能很简单：它遍历来自标准输入的行数据。由于这个迭代器会生成 Result 类型的数据，所以我们使用 ? 运算符来检查是否存在错误。

假设我们希望进一步扩展我们的 grep 程序，加入对磁盘上文件搜索功能的支持。我们可以让这个函数具有通用性：

fn grep<R>(target: &str, reader: R) -> io::Result<()>
where
    R: BufRead,
{
    for line_result in reader.lines() {
        let line = line_result?;
        if line.contains(target) {
            println!("{line}");
        }
    }
    Ok(())
}

现在我们可以传递一个 StdinLock 或缓冲后的 File 了：

grep(&target, io::stdin().lock())?;  // ok

let f = File::open(file)?;
grep(&target, BufReader::new(f))?;  // also ok

请注意， File 并不会自动被缓冲。 File 实现了 Read 的功能，但并未实现 BufRead 的功能。不过，对于 File 或其他未缓冲的读取器，很容易创建一个缓冲读取器。 BufReader::new(reader) 就是这么做的。（要设置缓冲的大小，可以使用 BufReader::with_capacity(size, reader) 。）


完整的程序代码包括错误处理和一些基本的参数解析功能，如下所示：

// grep - Search stdin or some files for lines matching a given string.

use std::error::Error;
use std::fs::File;
use std::io::prelude::*;
use std::io::{self, BufReader};
use std::path::PathBuf;

fn grep<R>(target: &str, reader: R) -> io::Result<()>
where
    R: BufRead,
{
    for line_result in reader.lines() {
        let line = line_result?;
        if line.contains(target) {
            println!("{line}");
        }
    }
    Ok(())
}

fn grep_main() -> Result<(), Box<dyn Error>> {
    // Get the command-line arguments. The first argument is the
    // string to search for; the rest are filenames.
    let mut args = std::env::args().skip(1);
    let target = match args.next() {
        Some(s) => s,
        None => Err("usage: grep PATTERN FILE...")?,
    };
    let files: Vec<PathBuf> = args.map(PathBuf::from).collect();

    if files.is_empty() {
        grep(&target, io::stdin().lock())?;
    } else {
        for file in files {
            let f = File::open(file)?;
            grep(&target, BufReader::new(f))?;
        }
    }

    Ok(())
}

fn main() {
    let result = grep_main();
    if let Err(err) = result {
        eprintln!("{err}");
        std::process::exit(1);
    }
}

收集行号


几种读取方法，包括 .lines() ，都会返回产生 Result 值的迭代器。当你试图将文件的所有行收集到一个大的向量中时，就会遇到处理 Result 的问题：

// ok, but not what you want
let results: Vec<io::Result<String>> = reader.lines().collect();

// error: can't convert collection of Results to Vec<String>
let lines: Vec<String> = reader.lines().collect();


第二次尝试时程序无法编译：那么这些错误会如何处理呢？一个简单的解决方案就是编写一个循环，逐一检查每个项目的正确性：

let mut lines = vec![];
for line_result in reader.lines() {
    lines.push(line_result?);
}


还不错；不过，如果能在这里使用 .collect() 的话就更好了。事实上，我们完全可以这样做。我们只需要知道应该请求哪种类型的数据即可。

let lines = reader.lines().collect::<io::Result<Vec<String>>>()?;


这是如何工作的呢？标准库中包含了一个针对 Result 的实现，这个实现在在线文档中很容易被忽视——不过，这个实现确实使得这一功能成为可能。

impl<T, E, C> FromIterator<Result<T, E>> for Result<C, E>
where
    C: FromIterator<T>,
{
    ...
}


这需要一些仔细的解析，但确实是一个不错的技巧。假设 C 可以是任何集合类型，比如 Vec 或 HashSet 。既然我们已经知道如何从一个包含 T 值的迭代器中构建 C ，那么我们就可以从一个产生 Result<T, E> 值的迭代器中构建 Result<C, E> 。我们只需要从迭代器中提取值，然后从这些结果中构建集合。不过，如果我们遇到 Err ，就停止操作并将其传递给下一个步骤。


换句话说， io::Result<Vec<String>> 是一种集合类型，因此 .collect() 方法可以创建并填充该类型的对象。

作家们


正如我们所看到的，输入通常是通过各种方法来实现的。而输出则有所不同。


在整本书中，我们一直使用 println!() 来生成纯文本输出：

println!("Hello, world!");
println!("The greatest common divisor of {numbers:?} is {d}");
println!();  // print a blank line


此外，还有 print!() 宏，它不会在末尾添加新行字符；而 eprintln! 和 eprint! 宏则会将输出内容写入标准错误流中。所有这些宏的格式化代码与 format! 宏的格式化代码相同，相关内容可以在“格式化值”部分找到。


要将输出数据发送到写入器，可以使用 write!() 和 writeln!() 宏。这两个宏与 print!() 和 println!() 相同，只是有两个区别：

writeln!(io::stderr(), "error: world not helloable")?;
writeln!(&mut byte_vec, "The greatest common divisor of {numbers:?} is {d}")?;


print 宏并不返回 Result 的值；当写入操作失败时，它们只会引发恐慌。由于这些操作是直接写入终端的，所以这种情况很少发生。


Write 特性包含以下方法：

writer.write(&buf)


将切片 buf 中的部分字节写入到底层流中。返回值为 io::Result<usize> 。如果操作成功，会返回写入的字节数，该数值可能小于 buf.len() ，因为流的操作结果具有不确定性。

就像 Reader::read() 那样，这种低级的方法应该直接避免使用。

writer.write_all(&buf)


写入切片 buf 中的所有字节。返回值为 Result<()> 。

writer.flush()


将所有缓冲的数据刷新到底层流中。返回值 Result<()> 。

请注意，虽然 println! 和 eprintln! 宏可以自动清空标准输出和标准错误流，但 print! 和 eprint! 宏则不能。在使用它们时，可能需要手动调用 flush() 宏。

就像读者一样，当作家们被删除时，他们的作品也会自动关闭。

就像 BufReader::new(reader) 为所有读取操作添加了缓冲器一样， BufWriter::new(writer) 也为所有写入操作添加了缓冲器：

let file = File::create("tmp.txt")?;
let writer = BufWriter::new(file);


当 BufWriter 被丢弃时，所有剩余的缓冲数据都会被写入到相应的写入器上。不过，如果在此过程中发生错误，该错误将被忽略。（因为这种情况发生在 BufWriter 的 .drop() 方法中，所以没有合适的地方可以报告这个错误。）为了确保你的应用程序能够检测到所有输出错误，请在丢弃这些数据之前手动处理这些缓冲写入器。

文件


我们已经看到了两种打开文件的方法：

File::open(filename)


打开一个已存在的文件以进行读取。如果文件不存在，则会返回 io::Result<File> 错误。

File::create(filename)


创建一个新的用于写入的文件。如果已经存在同名文件，那么该文件会被覆盖。


当这两种情况都不符合需求时，可以使用 OpenOptions 来指定确切所需的行为。

use std::fs::OpenOptions;

let log = OpenOptions::new()
    .append(true)  // if file exists, add to the end
    .open("server.log")?;

let file = OpenOptions::new()
    .write(true)
    .create_new(true)  // fail if file exists
    .open("new_file.txt")?;


这些方法 .append() 、 .write() 、 .create_new() 等都是设计为可以链式调用的：每个方法都会返回 self 。这种方法链式调用的设计模式在 Rust 中非常常见，因此被命名为“构建器”。 std::process::Command 是另一个例子。关于 OpenOptions 的更多细节，请参阅在线文档。


在现实世界的代码中，你可能会考虑使用 fs-err 这个包。它的工作原理与 std::fs 类似，不过它能生成更详细的错误信息。其 API 与 std::fs 完全相同，因此你只需在 Cargo.toml 文件中将其列为依赖项，然后修改代码中的导入语句即可。

use fs_err::OpenOptions;

let mut file = OpenOptions::new()
    .write(true)
    .create_new(true)
    .open("new_file.txt")?;
...

使用 std::fs::OpenOptions 时，可能会出现 File exists (os error 17) 的错误，而这一错误信息并不具有太多参考价值。 fs_err::OpenOptions 在每次操作过程中会占用更多的内存，从而能够生成包含更多信息的消息。

failed to open file `new_file.txt`: File exists (os error 17)

寻求


File 也实现了 Seek 特性，这意味着你可以在一个 File 内部进行跳转，而不是需要从开始一直读或写到一个地方。 Seek 的定义如下：

pub trait Seek {
    fn seek(&mut self, pos: SeekFrom) -> io::Result<u64>;
}

pub enum SeekFrom {
    Start(u64),
    End(i64),
    Current(i64),
}

得益于 enum 的引入， seek 方法变得更加直观易用：可以使用 file.seek(SeekFrom::Start(0)) 来回到开头，而使用 file.seek(SeekFrom::Current(-8)) 则可以向前移动几字节，以此类推。

在文件中查找内容的速度较慢。除非该文件完全存储在内存中，否则你可能需要花费与读取几兆字节数据相同的时间来查找所需的内容。

其他读者和写作者类型


到目前为止，这一章节以 File 作为示例对象，但实际上还有许多其他有用的读写类型：

io::stdin()


该接口返回一个用于读取标准输入流的读取器。其类型為 io::Stdin 。由于这个资源是由所有线程共享的，因此每次进行读取操作时，都需要获取并释放互斥锁。


Stdin 有一个 .lock() 方法，用于获取互斥锁并返回一个 io::StdinLock 对象。这个对象是一个缓冲读取器，能够持有互斥锁直到其被释放。因此，对 StdinLock 的单独操作就可以避免互斥锁带来的开销。

io::stdout(), io::stderr()


返回标准输出和标准错误流中的 Stdout 和 Stderr 类型的写入器。这些写入器也具有互斥机制，并且包含 .lock() 相关的方法。

Vec<u8>


执行 Write 操作。将新数据写入到 Vec<u8> 中，从而扩展该向量。


( String ，然而，它并没有实现 Write 的功能。要使用 Write 来构造一个字符串，首先需要将数据写入到 Vec<u8> 中，然后再使用 String::from_utf8(vec) 将向量转换为字符串。)

Cursor::new(buf)


创建一个 Cursor ，一个用于从 buf 读取数据的缓冲读取器。这就是如何创建一个从 String 读取数据的读取器的方法。参数 buf 可以是任何实现了 AsRef<[u8]> 的类型，因此你也可以传递 &[u8] 、 &str 或 Vec<u8> 作为参数。


Cursor 这些对象在内部是简单的结构。它们只有两个字段： buf 本身，以及一个整数，表示下一次读取操作开始的偏移量。这个偏移量初始值为 0。


光标实现了 Read 、 BufRead 和 Seek 功能。如果 buf 的类型为 &mut [u8] 或 Vec<u8> ，那么 Cursor 也实现了 Write 功能。向光标写入数据会覆盖 buf 中从当前位置开始的字节。如果尝试写入超过 &mut [u8] 的末尾位置，将会得到部分写入的结果，或者得到一个 io::Error 。不过，使用光标写入超过 Vec<u8> 的末尾位置是可行的：这样会扩展向量。因此， Cursor<&mut [u8]> 和 Cursor<Vec<u8>> 实现了所有四个 std::io::prelude 特性。

std::net::TcpStream


表示一种 TCP 网络连接。由于 TCP 支持双向通信，因此它既可以作为读取器，也可以作为写入器使用。

构造函数 TcpStream::connect(("hostname", PORT)) 试图连接到服务器，并返回了一个 io::Result<TcpStream> 。

std::process::Command


支持创建子进程，并将数据传递给其子进程的标准输入端口，具体方式如下：

use std::process::{Command, Stdio};

let mut child = Command::new("grep")
    .arg("-e")
    .arg("a.*e.*i.*o.*u")
    .stdin(Stdio::piped())
    .spawn()?;

let mut to_child = child.stdin.take().unwrap();
for word in my_words {
    writeln!(to_child, "{word}")?;
}
drop(to_child);  // close grep's stdin, so it will exit
child.wait()?;


类型 child.stdin 相当于 Option<std::process::ChildStdin> ；在创建子进程时，我们使用了 .stdin(Stdio::piped()) 作为参数，因此当 .spawn() 执行成功时， child.stdin 肯定会被填充。如果我们没有这样做，那么 child.stdin 就会等于 None 。

Command 也有类似的方法 .stdout() 和 .stderr() ，这些方法可以用来请求在 child.stdout 和 child.stderr 中的读者。

std::io::pipe()


std::process::Command 提供了许多用于创建命令管道的便捷方法，通常不需要亲自调用 std::io::pipe 。不过，在第 21 章中，我们会介绍一种使用管道的方法。


std::io 模块还提供了一些函数，可以生成简单的读取器与写入器：

io::sink()

这就是那个什么都不做的编写器。所有的写入方法都返回 Ok ，但数据实际上被丢弃了。

io::empty()

这是那个什么都不做的读取器。它总是能成功读取数据，但会在输入结束时报错。

二进制数据、压缩与序列化


许多开源项目都基于 std::io 框架来提供额外的功能。


byteorder 这个模块提供了 ReadBytesExt 和 WriteBytesExt 两种特性，这些特性为二进制输入和输出操作增加了相应的方法，使得所有读写操作都能得到妥善处理：

use byteorder::{LittleEndian, ReadBytesExt, WriteBytesExt};

let n = reader.read_u32::<LittleEndian>()?;
writer.write_i64::<LittleEndian>(n as i64)?;


flate2 这个 crate 提供了用于读取和写入 gzip 生理数据的方法：

use flate2::read::GzDecoder;
let file = File::open("access.log.gz")?; 
let mut gzip_reader = GzDecoder::new(file);


serde 这个 crate，以及与之相关的格式相关 crate，比如 serde_json ，实现了序列化和反序列化功能：它们能够将在 Rust 结构体中的数据转换为字节流，也能将字节流转换回 Rust 结构体。之前在“特质与他人的类型”一文中已经提到过这一点。现在我们可以更仔细地了解它们了。

假设我们有一些数据——一个文本冒险游戏的角色地图——这些数据存储在一个 HashMap :中。

type RoomId = String;                       // each room has a unique name
type RoomExits = Vec<(char, RoomId)>;       // ...and a list of exits
type RoomMap = HashMap<RoomId, RoomExits>;  // room names and exits, simple

// Create a simple map.
let mut map = RoomMap::new();
map.insert(
    "Cobble Crawl".to_string(),
    vec![('W', "Debris Room".to_string())],
);
map.insert(
    "Debris Room".to_string(),
    vec![
        ('E', "Cobble Crawl".to_string()),
        ('W', "Sloping Canyon".to_string()),
    ],
);
...

将这些数据转换为 JSON 格式输出只需要一行代码即可：

serde_json::to_writer(&mut std::io::stdout(), &map)?;

在内部设计中， serde_json::to_writer 使用了 serde::Serialize trait 中的 serialize 方法。该库会将此 trait 附加到所有能够进行序列化处理的类型上，而这些类型包括我们数据中出现的所有类型：字符串、字符、元组、向量，以及 HashMap 等。

serde 格式非常灵活。在这个程序中，输出数据是 JSON 格式，因为我们选择了 serde_json 序列化器。还有其他格式可供选择，比如 MessagePack 格式。此外，你还可以将输出数据保存到文件中，使用 Vec<u8> 格式，或者任何其他的写入方式。上面的代码将数据打印到 stdout 文件中。以下是具体的内容：

{"Debris Room":[["E","Cobble Crawl"],["W","Sloping Canyon"]],"Cobble Crawl":
[["W","Debris Room"]]}

serde 还支持推导出两个关键 serde 特性：

#[derive(Serialize, Deserialize)]
struct Player {
    location: String,
    items: Vec<String>,
    health: u32,
}


这个 #[derive] 属性可能会导致编译过程稍微慢一些，因此当你在 Cargo.toml 文件中将其列为依赖项时，需要明确声明支持这一特性。前面提到的代码中我们就使用了这一特性。

[dependencies]
serde = { version = "1.0.228", features = ["derive"] }
serde_json = "1.0.150"

更多细节请参考 serde 文档。简而言之，构建系统会自动为 Player 生成 serde::Serialize 和 serde::Deserialize 的实现，因此序列化 Player 值非常简单：

serde_json::to_writer(&mut std::io::stdout(), &player)?;


输出结果如下：

{"location":"Cobble Crawl","items":["a wand"],"health":3}

文件和目录


现在我们已经介绍了如何与文件和目录进行交互的方法，接下来的几节将介绍 Rust 在处理文件和目录方面的功能。所有这些功能都涉及到对文件名的操作，因此我们将从文件名的类型开始讲解。

OsStr 和 Path


不幸的是，你的操作系统并不强制要求文件名必须是有效的 Unicode 格式。以下是两条适用于 Linux shell 的命令，它们都可以创建文本文件。不过，只有第一条命令能够生成有效的 UTF-8 格式文件名：

$ echo "hello world" > ô.txt
$ echo "O brave new world, that has such filenames in't" > $'\xf4'.txt


这两个命令都可以无需任何注释就执行了，因为 Linux 内核并不认识 Ogg Vorbis 中的 UTF-8 编码。对内核来说，任何由字节组成的字符串（不包括空字节和斜杠）都可以作为文件名。在 Windows 系统中也是如此：几乎任何由 16 位“宽字符”组成的字符串都可以作为文件名，即使这些字符串不是有效的 UTF-16 编码。对于操作系统处理的其他字符串，比如命令行参数和环境变量，情况也是类似的。


Rust 中的字符串始终都是有效的 Unicode 编码。实际上，文件名也几乎总是采用 Unicode 格式，但 Rust 仍需处理那些不采用 Unicode 格式的情况。这就是为什么 Rust 中有 std::ffi::OsStr 和 OsString 这样的表示方式。


OsStr 是一种字符串类型，它是 UTF-8 的超集。它的作用是可以表示当前系统中的所有文件名、命令行参数以及环境变量，无论这些内容是有效的 Unicode 字符还是其他字符。在 Unix 系统中， OsStr 可以存储任何字节序列。而在 Windows 系统中， OsStr 则使用 UTF-8 的扩展形式来存储数据，能够编码任何 16 位值的序列，包括不匹配的替代字符。


最后，对于每种字符串类型，都对应着一种所属类型：一个 String 类型拥有堆分配到的 str 类型；一个 std::ffi::OsString 类型拥有堆分配到的 OsStr 类型；而一个 std::path::PathBuf 类型则拥有堆分配到的 Path 类型。表 18-1 列出了每种类型的一些特性。

这三种类型都实现了一种共同的特性，即 AsRef<Path> 。因此，我们可以轻松定义一个通用函数，该函数可以接受“任何类型的文件名”作为参数。这种技术我们在“AsRef 和 AsMut”中已经介绍过了。

use std::io;
use std::path::Path;

fn swizzle_file<P>(path_arg: P) -> io::Result<()>
where
    P: AsRef<Path>,
{
    let path = path_arg.as_ref();
    ...
}


所有那些接受 path 参数的标准函数和方法都采用了这种技术，因此你可以自由地将字符串字面量传递给它们中的任何一个。

路径和 PathBuf 相关的方法


Path 提供了以下方法，以及其他一些方法：

Path::new(str)


将 &str 或 &OsStr 转换为 &Path 。这个过程并不会复制字符串。新的 &Path 指向的字节与原始的 &str 或 &OsStr 相同。

use std::path::Path;
let home_dir = Path::new("/home/fwolfe");

（类似的方法 OsStr::new(str) 可以将 &str 转换为 &OsStr 。）

path.parent()


如果有的话，该函数会返回路径的父目录路径。返回的类型是 Option<&Path> 。

这个路径并没有复制原来的路径。 path 的父目录始终也是 path 的子目录。

assert_eq!(
    Path::new("/home/fwolfe/program.txt").parent(),
    Some(Path::new("/home/fwolfe")),
);
path.file_name()


返回 path 的最后一个组件，如果有的话。返回的类型是 Option<&OsStr> 。

在典型的情况下，当 path 表示一个包含目录、斜线以及文件名的结构时，这种方式可以返回文件名：

use std::ffi::OsStr;
assert_eq!(
    Path::new("/home/fwolfe/program.txt").file_name(),
    Some(OsStr::new("program.txt")),
);
path.is_absolute(), path.is_relative()


这些标记了文件是绝对路径，比如 Unix 路径/usr/bin/advent，或者相对路径，比如 src/main.rs。

path1.join(path2)


连接两条路径，返回一个新的 PathBuf ：

let path1 = Path::new("/usr/share/dict");
assert_eq!(
    path1.join("words"),
    Path::new("/usr/share/dict/words"),
);

如果 path2 是一个绝对路径，那么这个方法会返回 path2 的副本。因此，可以使用这个方法将任何路径转换为绝对路径。

let abs_path = std::env::current_dir()?.join(any_path);
path.components()


该迭代器按从左到右的顺序返回给定路径中各个组成部分的迭代器。这个迭代器的元素类型是一个枚举值 std::path::Component ，该枚举可以表示文件名中可能出现的所有不同部分。

pub enum Component<'a> {
    Prefix(PrefixComponent<'a>),  // a drive letter or share (on Windows)
    RootDir,                      // the root directory, `/` or `\`
    CurDir,                       // the `.` special directory
    ParentDir,                    // the `..` special directory
    Normal(&'a OsStr),            // plain file and directory names
}


例如，Windows 路径\\venice\Music\A Love Supreme\04-Psalm.mp3 由几个组件构成：第一个组件是 Prefix ，代表\\venice\Music；接着是一个 RootDir ；最后有两个 Normal 组件，分别代表 A Love Supreme 和 04-Psalm.mp3。


有关详细信息，请参考在线文档。

path.ancestors()


该接口返回一个迭代器，该迭代器从 path 开始遍历到根节点。每次迭代返回的是一个 Path 对象：首先是该 path 对象本身，然后是它的父节点，再然后是它的祖父节点，以此类推。

let file = Path::new("/home/jimb/calendars/calendar-18x18.pdf");
assert_eq!(
    file.ancestors().collect::<Vec<_>>(),
    vec![
        Path::new("/home/jimb/calendars/calendar-18x18.pdf"),
        Path::new("/home/jimb/calendars"),
        Path::new("/home/jimb"),
        Path::new("/home"),
        Path::new("/"),
    ],
);

这就像反复调用 parent ，直到它返回 None 。最后一个项总是根路径或前缀路径。


将 Path 转换为字符串有三种方法。每种方法都考虑了 Path 中可能存在的无效 UTF-8 编码情况。

path.to_str()


将 Path 转换为字符串，结果为 Option<&str> 。如果 path 不是有效的 UTF-8 编码，那么会返回 None ：

if let Some(file_str) = path.to_str() {
    println!("{file_str}");
}  // ...otherwise skip this weirdly named file
path.to_string_lossy()


基本上都是同样的事情，但这些方法在任何情况下都能返回一个字符串。如果 path 不是有效的 UTF-8 编码，这些方法会复制原始字符串，并将每个无效的字节序列替换为 Unicode 替换字符 U+FFFD（�）。


返回类型为 std::borrow::Cow<str> ：它是一个被借用或拥有的字符串。要获取该值的 String ，可以使用其 .to_owned() 方法。（关于 Cow 的更多信息，请参见“借用与拥有：卑微的奶牛”）。

path.display()


这是用于打印路径的：

println!("Download found. You put it in: {}", dir_path.display());


这个返回值不是一个字符串，而是实现了 std::fmt::Display 的接口。因此，它可以与 format!() 、 println!() 等类似的接口一起使用。如果路径不是有效的 UTF-8 编码，那么输出中可能會包含�字符。

读取目录


要列出一个目录中的内容，可以使用 std::fs::read_dir ，或者等效地，使用 Path 中的 .read_dir() 方法：

for entry_result in path.read_dir()? {
    let entry = entry_result?;
    println!("{}", entry.file_name().to_string_lossy());
}


类型 entry 相当于 std::fs::DirEntry ，它是一个结构体，只包含几个方法：

entry.file_name()


文件的名称或目录的名称，格式为 OsString 。

entry.path()


情况是一样的，只不过原来的路径被合并到了一起，从而产生了新的 PathBuf 。如果我们正在列出的目录是 "/home/jimb" ，而 entry.file_name() 是 ".emacs" ，那么 entry.path() 就会返回 PathBuf::from("/home/jimb/.emacs") 。

entry.file_type()


返回一个对象。该对象包含 .is_file() 、 .is_dir() 和 .is_symlink() 这些方法。

entry.metadata()


获取关于此条记录的其余元数据信息。


在读取目录时，特殊的目录 . 和 .. 并未被列出。

这里有一个更典型的例子。以下代码递归地将一个目录树从一处复制到另一处磁盘上：

use std::fs;
use std::io;
use std::path::Path;

/// Copies the existing directory `src` to the target path `dst`.
fn copy_dir_to(src: &Path, dst: &Path) -> io::Result<()> {
    if !dst.is_dir() {
        fs::create_dir(dst)?;
    }

    for entry_result in src.read_dir()? {
        let entry = entry_result?;
        let file_type = entry.file_type()?;
        copy_to(&entry.path(), &file_type, &dst.join(entry.file_name()))?;
    }

    Ok(())
}


还有一个独立的函数 copy_to ，可以用于复制单个目录条目：

/// Copies whatever is at `src` to the target path `dst`.
fn copy_to(src: &Path, src_type: &fs::FileType, dst: &Path) -> io::Result<()> {
    if src_type.is_file() {
        fs::copy(src, dst)?;
    } else if src_type.is_dir() {
        copy_dir_to(src, dst)?;
    } else {
        return Err(io::Error::other(
            format!("don't know how to copy: {}", src.display()),
        ));
    }
    Ok(())
}

平台特有功能


到目前为止，我们的 copy_to 函数可以复制文件和目录。如果我们还想在 Unix 系统上支持符号链接，那该怎么办呢？


没有一种可以在 Unix 和 Windows 系统上都适用的方法来创建符号链接。不过，标准库提供了一个专用于 Unix 系统的 symlink 函数。

use std::os::unix::fs::symlink;

这样一来，我们的任务就变得简单了。我们只需在 copy_to 中的 if 表达式后面添加一个分支即可：

...
} else if src_type.is_symlink() {
    let target = src.read_link()?;
    symlink(target, dst)?;
...

#[cfg(target_os = "macos")]     pub mod macos;
...


#[cfg] 属性表示条件编译：这些模块只在某些平台上存在。这就是为什么使用 std::os::unix 的修改后的程序只能成功在 Unix 平台上编译——在其他平台上， std::os::unix 并不存在。

如果我们希望代码能在所有平台上编译，并且能在 Unix 系统上支持符号链接功能，那么我们在程序中必须使用 #[cfg] 。在 Unix 系统上，可以直接导入 symlink ；而在其他系统中，则需要定义自己的 symlink 接口。

#[cfg(unix)]
use std::os::unix::fs::symlink;

/// Stub implementation of `symlink` for platforms that don't provide it.
#[cfg(not(unix))]
fn symlink<P: AsRef<Path>, Q: AsRef<Path>>(
    src: P,
    _dst: Q,
) -> std::io::Result<()> {
    Err(io::Error::other(
        format!("can't copy symbolic link: {}", src.as_ref().display()),
    ))
}


显然， symlink 是一个特殊的案例。大多数与 Unix 相关的特性并非独立的函数，而是作为扩展特性存在，它们为标准库类型增加了新的方法。（我们在“特性类与其他人的类型”一文中讨论过扩展特性。）有一个名为 prelude 的模块，可以用来一次性启用所有这些扩展功能。

use std::os::unix::prelude::*;


例如，在 Unix 系统中，这样做会在 std::fs::Permissions 上添加 .mode() 方法，从而可以访问代表 Unix 权限的底层 u32 值。同样地，它还会为底层 struct stat 值的各个字段添加访问器，比如 .uid() ，即文件所有者的用户 ID。


总的来说， std::os 中的功能相当基础。而更多与特定平台相关的功能可以通过第三方库来实现，比如 winreg ，它可以帮助访问 Windows 注册表。

建立人脉关系/社交网络


关于网络编程的教程已经超出了本书的范围。不过，如果你已经对网络编程有一些了解，那么这一部分将会帮助你开始使用 Rust 语言进行网络编程。


在低级网络编程中，建议先使用 std::net 模块，它提供了对 TCP 和 UDP 网络的跨平台支持。如果需要处理 SSL/TLS 协议，则可以使用 native_tls crate。


这些模块提供了基于网络进行简单输入和输出处理的基础。你只需几行代码就能编写一个简单的服务器，并使用 std::net 来为每个连接创建一个线程。例如，下面是一个“回声”服务器示例：

use std::net::TcpListener;
use std::{io, thread};

/// Accepts connections forever, spawning a thread for each one.
fn echo_main(addr: &str) -> io::Result<()> {
    let listener = TcpListener::bind(addr)?;
    println!("listening on {addr}");
    loop {
        // Wait for a client to connect.
        let (mut stream, addr) = listener.accept()?;
        println!("connection received from {addr}");

        // Spawn a thread to handle this client.
        let mut write_stream = stream.try_clone()?;
        thread::spawn(move || {
            // Echo everything we receive from `stream` back to it.
            io::copy(&mut stream, &mut write_stream)
                .expect("error in client thread: ");
            println!("connection closed");
        });
    }
}

fn main() {
    echo_main("127.0.0.1:17007").expect("error: ");
}


回音服务器只是重复发送你传递给它的所有内容。这种代码与用 Java 或 Python 编写的代码并没有太大区别。（我们将在下一章详细介绍 std::thread::spawn() 。）


不过，对于高性能服务器来说，就需要使用异步输入和输出功能了。第 20 章介绍了 Rust 对异步编程的支持。


一些更高级别的协议也得到了第三方 crate 的支持。例如， reqwest crate 提供了一个出色的 HTTP 客户端 API。下面是一个完整的命令行程序，它可以获取任何包含 http: 或 https: 的 URL 的文档，并将其输出到终端。这段代码是使用 reqwest = "0.13.4" 编写的，同时启用了其 "blocking" 功能。 reqwest 还提供了一个异步接口。

use std::error::Error;
use std::io;

fn http_get_main(url: &str) -> Result<(), Box<dyn Error>> {
    // Send the HTTP request and get a response.
    let mut response = reqwest::blocking::get(url)?;
    if !response.status().is_success() {
        Err(format!("{}", response.status()))?;
    }

    // Read the response body and write it to stdout.
    let stdout = io::stdout();
    io::copy(&mut response, &mut stdout.lock())?;

    Ok(())
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    if args.len() != 2 {
        eprintln!("usage: http-get URL");
        return;
    }

    if let Err(err) = http_get_main(&args[1]) {
        eprintln!("error: {err}");
    }
}


HTTP 服务器的 actix-web 框架提供了高级特性，比如 Service 和 Transform 这些接口，它们帮助你将应用程序拆分成可复用的部分。 websocket 模块则实现了 WebSocket 协议。而 Rust 是一种新兴的语言，其开源生态系统正在迅速发展。对网络处理的支持也在不断扩展中。
