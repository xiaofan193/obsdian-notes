迭代器是一种能够生成一系列值的对象，通常用于循环操作。Rust 的标准库提供了多种迭代器，可以用来遍历向量、字符串、哈希表以及其他集合类型。此外，迭代器还可以用于从输入流中提取文本行、处理网络服务器上的连接信息，以及从通信渠道接收来自其他线程的数据等。当然，你也可以根据自己的需求自定义迭代器。Rust 的 for 循环结构为使用迭代器提供了自然的语法，而迭代器本身也提供了丰富的操作方法，比如映射、过滤、连接、收集等。


Rust 的迭代器具有灵活性、表达力强且效率高。考虑以下这个函数，它用于计算前 n 个正整数的和（通常称为第 n 个三角数）：

fn triangle(n: i32) -> i32 {
    let mut sum = 0;
    for i in 1..=n {
        sum += i;
    }
    sum
}


不过，迭代器也有一个名为 fold 的方法，你可以在相应的定义中使用它：

fn triangle(n: i32) -> i32 {
    (1..=n).fold(0, |sum, item| sum + item)
}


对于功能性的编程语言来说，这种处理方式相当常见，因为这些语言非常注重表达的清晰性。不过，Rust 的迭代器设计得非常精巧，确保编译器能够将它们转换为高效的机器代码。在之前展示的第二个版本中，Rust 能够识别 fold 的定义，并将其内联到 triangle 中。接下来，闭包 |sum, item| sum + item 也被内联到 triangle 中。最后，Rust 会分析整个代码，发现有一个更简单的办法来计算从 1 到 n 的数字之和：这个和始终等于 n * (n + 1) / 2 。Rust 将 triangle 中的所有代码、循环、闭包等元素，都转化为单一的乘法操作以及一些其他算术运算。

这个例子涉及的是简单的算术运算，不过迭代器在需要处理更复杂任务时同样表现出良好的性能。这再次证明了 Rust 提供的灵活抽象机制在常规使用场景中几乎不会造成额外的负担。

在本章中，我们将解释以下内容：


  • Iterator 和 IntoIterator 这些特性，正是 Rust 迭代器的基础所在。


  • 典型的迭代器处理流程包含三个阶段：首先从某种值源创建迭代器；通过选择或处理经过的值来将一种迭代器转换为另一种迭代器；最后消耗由迭代器产生的这些值。

  • 如何为自己的类型实现迭代器机制

有很多种方法可以实现相同的功能，所以当你已经大致了解基本情况后，可以跳过某些部分。不过，在 Rust 语言中，迭代器是非常常见的概念，熟悉与之相关的工具对于掌握这门语言至关重要。

Iterator 和 IntoIterator 特性


迭代器是指任何实现了 std::iter::Iterator 特质的值：

trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
    ...  // many default methods
}


Item 是迭代器所生成的值的类型。 next 方法会返回 Some(v) ，其中 v 是迭代器的下一个值；或者返回 None ，表示序列的结束。在这里，我们省略了 Iterator 的许多默认方法；我们将在本章的后续部分分别介绍它们。

如果有一种自然的方法可以遍历某种类型的数据，那么这种类型可以实现 std::iter::IntoIterator 接口，该接口的 into_iter 方法接受一个值，并返回一个对该值的迭代器。

trait IntoIterator
where
    Self::IntoIter: Iterator<Item = Self::Item>,
{
    type Item;
    type IntoIter: Iterator;
    fn into_iter(self) -> Self::IntoIter;
}


IntoIter 是迭代器的值本身的类型，而 Item 则是它所生成值的类型。任何实现了 IntoIterator 接口的类型都被称为可迭代对象，因为如果你愿意的话，你可以对其执行迭代操作。

Rust 中的 for 循环很好地将所有这些部分连接了起来。要遍历向量中的元素，可以这样写：

println!("There's:");
let v = vec!["antimony", "arsenic", "aluminum", "selenium"];

for element in &v {
    println!("{element}");
}

在底层，每一个 for 循环其实都是对 IntoIterator 和 Iterator 方法的调用简写形式。

let mut iterator = (&v).into_iter();
while let Some(element) = iterator.next() {
    println!("{element}");
}


循环 for 使用 IntoIterator::into_iter 将其操作数 &v 转换为迭代器，然后反复调用 Iterator::next 。每次调用 Iterator::next 都会返回 Some(element) ，此时 for 循环会执行其内部代码；如果返回的是 None ，那么循环就结束。

考虑到这个例子，以下是一些关于迭代器的术语：


  • 正如我们所说，迭代器是指任何实现了 Iterator 功能的类型。


  • 可迭代对象是指那些实现了 IntoIterator 接口的任何类型。通过调用其 into_iter 方法，就可以获取该对象的迭代器。在这个例子中，向量引用 &v 就代表那个可迭代对象。


  • 迭代器用于生成值。


  • 迭代器产生的结果就是各个项。这里的项分别是 "antimony" 、 "arsenic" 等。


  • 由迭代器产生数据的接收者就是处理这些数据的部分。在这个例子中， for 循环就是负责处理这些数据的部分。


虽然 for 循环总是会调用其操作数上的 into_iter ，但您也可以直接将迭代器传递给 for 循环。例如，在遍历 Range 时就可以这样做。所有的迭代器都自动实现了 IntoIterator 接口，并且包含一个 into_iter 方法，该方法只需返回迭代器本身即可。


如果在一个迭代器返回 None 之后，再次调用其 next 方法，那么 Iterator 特性并不会指定应该执行什么操作。大多数迭代器会再次返回 None ，但并非所有迭代器都是如此。（如果这引起了问题，可以使用“fuse”中的 fuse 适配器来解决问题。）

创建迭代器


Rust 标准库文档详细说明了每种类型所提供的迭代器类型。不过，该库遵循一些通用规范，以便让你能够轻松找到所需的内容。

iter 和 iterMut 方法


大多数集合类型都有适用于其元素的迭代算法。对于 Vec 类型，就是逐步递增索引；对于 LinkedList 类型，则是依次访问每个节点。这类集合提供了 iter 和 iter_mut 方法，这些方法可以返回该类型的自然迭代器，从而为每个元素提供一个共享或可变的引用。类似数组切片的功能也有 &[T] 和 &mut [T] 方法。如果你不想让 for 循环自己处理这些迭代，那么这些方法就是获取迭代器的最常见方式。

let v = vec![4, 20, 12, 8, 6];
let mut iterator = v.iter();
assert_eq!(iterator.next(), Some(&4));
assert_eq!(iterator.next(), Some(&20));
assert_eq!(iterator.next(), Some(&12));
assert_eq!(iterator.next(), Some(&8));
assert_eq!(iterator.next(), Some(&6));
assert_eq!(iterator.next(), None);


每种类型都可以以最合适的方式来实现 iter 和 iter_mut 的功能。 std::path::Path 中的 iter 方法会返回一个迭代器，该迭代器会依次生成每个路径组件。

use std::ffi::OsStr;
use std::path::Path;

let path = Path::new("C:/Users/JimB/Downloads/Fedora.iso");
let mut iterator = path.iter();
assert_eq!(iterator.next(), Some(OsStr::new("C:")));
assert_eq!(iterator.next(), Some(OsStr::new("Users")));
assert_eq!(iterator.next(), Some(OsStr::new("JimB")));
...

这个迭代器的项类型是 &std::ffi::OsStr ，它是一个字符串的借用版本，属于那种可以被操作系统调用所接受的字符串类型。

如果有一种以上的常见方式可以遍历某个类型，那么这个类型通常会为每种遍历方式提供专门的方法。因为单纯的 iter 方法可能会造成歧义。例如， &str 字符串切片类型并没有 iter 方法。相反，如果 s 是 &str ，那么 s.bytes() 会返回一个迭代器，该迭代器会生成 s 中的每个字节；而 s.chars() 则会将内容视为 UTF-8 编码，并生成每个 Unicode 字符。

实现 IntoIterator 的方法


当某个类型实现了 IntoIterator 接口时，你就可以像使用 for 循环一样，直接调用其 into_iter 方法。

// You should usually use HashSet, but its iteration order is
// nondeterministic, so BTreeSet works better in examples.
use std::collections::BTreeSet;
let mut favorites = BTreeSet::new();
favorites.insert("Lucy in the Sky With Diamonds".to_string());
favorites.insert("Liebesträume No. 3".to_string());

let mut it = favorites.into_iter();
assert_eq!(it.next(), Some("Liebesträume No. 3".to_string()));
assert_eq!(it.next(), Some("Lucy in the Sky With Diamonds".to_string()));
assert_eq!(it.next(), None);


实际上，大多数集合类型都提供了多种实现方式：共享引用（ &T ）、可修改引用（ &mut T ），以及移动引用（ T ）。


  • 如果有一个对集合的共享引用，那么 into_iter 会返回一个迭代器，该迭代器能够生成对其元素的共享引用。例如，在上面的代码中， (&favorites).into_iter() 会返回一个迭代器，而这个迭代器的 Item 类型正是 &String 。


  • 如果给定了集合的可变引用，那么 into_iter 就会返回一个迭代器，该迭代器能够生成对集合元素的可变引用。例如，如果 vector 是某个 Vec<String> ，那么通过 (&mut vector).into_iter() 调用该迭代器，其 Item 类型的返回值就是 &mut String 。


  • 当通过值传递集合时， into_iter 会返回一个迭代器，该迭代器会负责管理该集合，并以值方式返回集合中的元素；这些元素的所有权会从集合转移到了消费者手中，而原始集合则会被处理掉。例如，在上面的代码中，调用 favorites.into_iter() 会返回一个迭代器，该迭代器会以值方式逐个返回字符串；消费者会获得每个字符串的所有权。当该迭代器被删除时， BTreeSet 中剩余的所有元素也会被处理掉，从而释放掉这个已经空无一物的集合。


由于 for 循环会将其中的 IntoIterator::into_iter 应用于其操作数，因此这三种实现方式实际上为遍历集合中的共享或可变引用、或者消耗集合并获取其元素的所有权提供了便利的编程技巧。

for element in &collection { ... }
for element in &mut collection { ... }
for element in collection { ... }

这些每一种方式最终都会触发对这里列出的某个 IntoIterator 实现的调用。

并非每种类型都实现了这三种功能。例如， HashSet 、 BTreeSet 和 BinaryHeap 并没有在可变的引用上实现 IntoIterator 的功能，因为修改它们的元素可能会违反类型的不变式：修改后的值可能会具有不同的哈希值，或者与邻近元素的关系也会发生改变，因此修改后会导致错误的排列。其他类型虽然支持修改操作，但只是部分实现了这一功能。例如， HashMap 和 BTreeMap 能够产生可变的条目值，但只能以共享引用的方式访问键，原因与上述情况类似。


切片实现了三种变体中的两种；由于切片不拥有其元素，因此不存在“按值传递”的情况。相反， into_iter 对 &[T] 和 &mut [T] 返回一个迭代器，该迭代器可以生成对元素的共享可变引用。如果你将底层切片类型 [T] 视为某种集合，那么这种实现方式就完全符合整体的设计模式了。


IntoIterator 正是让 for 循环能够工作的关键，因此显然是必要的。不过，当不需要使用 for 循环时，使用 favorites.iter() 而不是 (&favorites).into_iter() 来编写代码会更加清晰。通过共享引用进行迭代是经常需要使用的功能，因此 iter 和 iter_mut 在易用性方面仍然具有很高的价值。


IntoIterator 在通用代码中也可以发挥作用：你可以使用类似 T: IntoIterator 的绑定方式，来限制类型变量 T 只能适用于可以迭代的类型。或者，你可以写成 T: IntoIterator<Item = U> ，以进一步要求迭代结果必须是特定类型 U 。例如，这个函数可以输出任何可迭代对象的值，这些值的项目可以使用 "{:?}" 格式进行打印。

use std::fmt::Debug;

fn dump<T, U>(t: T)
where
    T: IntoIterator<Item = U>,
    U: Debug,
{
    for u in t {
        println!("{u:?}");
    }
}


你无法使用 iter 和 iter_mut 来编写这个通用函数，因为它们并不是任何 trait 的方法。大多数可迭代类型实际上都有名为这些名称的方法而已。

从 fn 开始的所有后续项


生成一系列值的简单通用方法就是提供一个能够返回这些值的闭包函数。

如果一个函数返回了 Option<T> ，那么 std::iter::from_fn 就会返回一个迭代器，这个迭代器会直接调用该函数来生成其输出内容。例如：

// Cargo.toml: rand = "0.10.1"
use std::iter;

// Generate the lengths of 1000 random line segments whose endpoints
// are uniformly distributed across the interval [0, 1]. (This isn't a
// distribution you're going to find in the `rand_distr` crate, but
// it's easy to make yourself.)
let lengths: Vec<f64> =
    iter::from_fn(|| {
        Some((rand::random::<f64>() - rand::random::<f64>()).abs())
    })
    .take(1000)
    .collect();


这调用了 from_fn ，以创建一个生成随机数的迭代器。由于该迭代器始终返回 Some ，因此序列永远不会结束。但我们使用 take(1000) 来限制只获取前 1,000 个元素。然后 collect 利用这些元素构建最终的向量。这是一种构建初始化向量的高效方法；关于为什么需要这样做，我们将在本章后面的“构建集合：collect 和 FromIterator”部分进行解释。

如果每个元素都依赖于前一个元素，那么使用 std::iter::successors 函数来表达这种关系是非常合适的。下面是我们对著名的 Collatz 过程的一种实现方式：

fn collatz_iterations(n: u64) -> u64 {
    let next = |n| match n {
        1 => None,
        n if n % 2 == 0 => Some(n / 2),
        n => Some(3 * n + 1),
    };

    iter::successors(next(n), |&n| next(n))
        .count() as u64
}


from_fn 和 successors 都接受 FnMut 类型的闭包，因此你的闭包可以捕获并修改来自周围作用域的变量。例如，这个 fibonacci 函数使用了一个 move 闭包来捕获一个变量，并将其作为运行时的状态使用。

fn fibonacci() -> impl Iterator<Item = usize> {
    let mut state = (0, 1);
    std::iter::from_fn(move || {
        state = (state.1, state.0 + state.1);
        Some(state.0)
    })
}

assert_eq!(
    fibonacci().take(8).collect::<Vec<_>>(),
    vec![1, 1, 2, 3, 5, 8, 13, 21],
);


请注意： from_fn 和 successors 方法具有足够的灵活性，你可以将迭代器的使用方式简化为对其中一个方法的单次调用，通过传递复杂的闭包来实现所需的行为。不过，这样做会忽略迭代器所带来的明确数据流动路径的机会，也无法利用迭代器为常见模式提供标准化的命名方式。在依赖这两种方法之前，请确保你已经熟悉本章中其他迭代器方法的使用；通常存在更优的实现方式来完成任务。

排水方法


许多集合类型都提供了一个 drain 方法，该方法接受一个可变的集合引用，并返回一个迭代器，该迭代器会将每个元素的所有权传递给调用者。不过，与 into_iter() 方法不同， into_iter() 方法是以值的形式接收集合并直接使用它，而 drain 方法只是借用了一个可变的集合引用。当迭代器被销毁时， drain 方法会移除集合中的剩余元素，使集合变为空状态。

对于那些可以通过范围索引的类型，比如 String s、向量以及 VecDeque s， drain 方法可以指定要移除的元素范围，而无需遍历整个序列：

let mut outer = "Earth".to_string();
let inner = String::from_iter(outer.drain(1..4));

assert_eq!(outer, "Eh");
assert_eq!(inner, "art");


如果你确实需要处理整个序列，可以使用完整的范围作为参数，即 .. 。

迭代器适配器


一旦你拥有了一个迭代器， Iterator 特质就提供了多种适配器方法，这些方法能够消耗一个迭代器并生成一个具有特殊行为的新的迭代器。为了了解适配器的工作原理，我们将从两种最常用的适配器开始介绍： map 和 filter 。之后，我们还会介绍其他各种适配器方法，包括从其他序列中生成值序列的各种方式：截断、跳过、组合、反转、连接、重复等等。

映射与过滤


Iterator trait 的 map 适配器允许你通过应用闭包来修改迭代器中的元素。 filter 适配器则允许你过滤出迭代器中的某些元素，通过闭包来决定哪些元素被保留，哪些被丢弃。


例如，假设您正在遍历文本行，想要从每一行中去除开头和结尾的空白字符。标准库中的 str::trim 方法会从一个 &str 对象中移除开头和结尾的空白字符，从而返回一个新的、已修剪后的 &str 对象，该对象会借用原始对象的数据。您可以使用 map 适配器来对迭代器中的每一行应用 str::trim 操作：

let text = "  ponies  \n   giraffes\niguanas  \nsquid".to_string();
let v: Vec<&str> = text
    .lines()
    .map(str::trim)
    .collect();
assert_eq!(v, ["ponies", "giraffes", "iguanas", "squid"]);


text.lines() 的调用返回一个迭代器，该迭代器可以处理字符串中的各行。对那个迭代器调用 map ，会得到一个新的迭代器，该迭代器会对每一行应用 str::trim 操作，并将结果作为其元素输出。最后， collect 将这些元素收集到一个向量中。


map 返回的迭代器本身也值得进行进一步的改造。如果你想要将伊瓜纳龟排除在结果之外，可以这样编写代码：

let text = "  ponies  \n   giraffes\niguanas  \nsquid".to_string();
let v: Vec<&str> = text
    .lines()
    .map(str::trim)
    .filter(|s| *s != "iguanas")
    .collect();
assert_eq!(v, ["ponies", "giraffes", "squid"]);

在这里， filter 返回一个第三个迭代器，该迭代器仅返回那些来自 map 迭代器的元素，这些元素的闭包 |s| *s != "iguanas" 会返回 true 。迭代器适配器就像一个管道系统，在 Unix shell 中非常常见：每个适配器都有明确的功能，而且从左到右阅读时，可以清楚地了解数据是如何被转换的。

这些适配器的签名如下：

fn map<B, F>(self, f: F) -> impl Iterator<Item = B>
where
    Self: Sized,
    F: FnMut(Self::Item) -> B;

fn filter<P>(self, predicate: P) -> impl Iterator<Item = Self::Item>
where
    Self: Sized,
    P: FnMut(&Self::Item) -> bool;


在标准库中， map 和 filter 实际上返回了两种特定的不透明类型，分别命名为 std::iter::Map 和 std::iter::Filter 。不过，仅仅看到它们的名称并不能提供太多信息。因此，在本书中，我们决定用 -> impl Iterator<Item = ...> 来表示它们，因为这样能更清楚地表明我们真正想要了解的是：这个方法返回一个 Iterator 对象，而该对象能够生成指定类型的元素。


由于大多数适配器都是按值传递参数，因此它们要求参数 Self 必须等于 Sized （而所有常见的迭代器都满足这个条件）。

一个 map 迭代器会将每个元素以值的形式传递给其闭包，并同时将闭包的结果的所有权传递给消费者。而一个 filter 迭代器则使用共享引用将每个元素传递给其闭包，如果元素被选中需要继续传递给下一个消费者，那么迭代器仍然拥有该元素的所有权。这就是为什么需要解引用 s 来与 "iguanas" 进行比较： filter 迭代器的元素类型是 &str ，因此闭包的参数 s 的类型就是 &&str 。

关于迭代器适配器，有两点需要注意的重要事项。


所以在之前的例子中，方法调用 text.lines() 实际上并没有解析字符串中的任何行；它只是返回一个迭代器，当被调用时，这个迭代器会负责解析这些行。同样地， map 和 filter 也只是返回新的迭代器，当被调用时，这些迭代器可以执行映射或过滤操作。直到 collect 在 filter 的迭代器上调用 next 之前，都不会发生任何操作。

如果你使用了那些带有副作用的适配器，那么这个问题就尤为重要了。例如，这段代码根本不会输出任何内容：

["earth", "water", "air", "fire"]
    .iter()
    .map(|elt| println!("{elt}"));


iter 调用的返回一个遍历数组元素的迭代器，而 map 调用的则返回一个另一个迭代器，该迭代器会将闭包应用于第一个迭代器产生的每个值。但实际上，整个过程中并没有任何情况需要从整个序列中获取值，因此没有任何 next 方法能够运行。事实上，Rust 会就此发出警告：

warning: unused `std::iter::Map` that must be used
  |
7 | /     ["earth", "water", "air", "fire"]
8 | |         .iter()
9 | |         .map(|elt| println!("{elt}"));
  | |_____________________________________^
  |
  = note: iterators are lazy and do nothing unless consumed


第二个重要点是，迭代器适配器是一种零开销的抽象机制。由于 map 、 filter 等组件都是通用的，将它们应用于迭代器意味着可以为特定的迭代器类型定制相应的代码。这意味着 Rust 拥有足够的信息，可以将每个迭代器的 next 方法内联到其消费者代码中，然后将整个操作转换为机器代码。因此，之前提到的这一系列迭代器实现，其效率与你手动编写的代码相当。

for line in text.lines() {
    let line = line.trim();
    if line != "iguanas" {
        v.push(line);
    }
}


本节的其余部分将介绍在 Iterator trait 上可用的各种适配器。

filter_map 和 flat_map


在每种传入数据对应一个输出数据的情况下， map 适配器已经足够好了。但如果你想要删除某些数据，而不是继续处理它们，或者用零个或多个数据来替换单个数据，那么 filter_map 和 flat_map 适配器就能满足你的需求。


filter_map 适配器与 map 类似，不过它允许其闭包将元素转换为新的元素（就像 map 所做的那样），或者直接丢弃该元素。因此，它有点像是 filter 和 map 的结合体。其签名如下：

fn filter_map<B, F>(self, f: F) -> impl Iterator<Item = B>
where
    Self: Sized,
    F: FnMut(Self::Item) -> Option<B>;

这与 map 的签名相同，只不过这里的闭包返回的是 Option<B> ，而不是简单的 B 。当闭包返回 None 时，该元素会从迭代中移除；而当它返回 Some(b) 时，那么 b 就会成为 filter_map 迭代器下一个产生的元素。

例如，假设你想扫描一个字符串，找出那些由空格分隔的单词，这些单词可以被解析为数字，然后处理这些数字，而忽略其他的单词。你可以这样写：

use std::str::FromStr;

let text = "1\nfrond .25  289\n3.1415 estuary\n";
for number in text
    .split_whitespace()
    .filter_map(|w| f64::from_str(w).ok())
{
    println!("{number:4.2}");
}

这将输出如下内容：

1.00
0.25
289.00
3.14


对 filter_map 进行的解析尝试使用 f64::from_str 来解析每个由空白字符分隔的片段。这样就能得到一个 Result<f64, ParseFloatError> 的结果，而 .ok() 则会将这个 Result<f64, ParseFloatError> 转换为 Option<f64> 格式：如果解析失败，则会产生 None 结果；如果解析成功，则会得到 Some(v) 的结果。 filter_map 迭代器会收集所有 None 的值，然后为每个 Some(v) 生成 v 的值。

但是，将 map 和 filter 合并为一次操作有什么意义呢？而不是直接使用那些适配器。在像刚才提到的这种情况下， filter_map 适配器就发挥了其作用——在决定是否将某个元素纳入迭代处理时，最好的方法就是实际尝试处理它。同样的事情也可以用 filter 和 map 来实现，不过那样做会显得有些笨拙了。

text.split_whitespace()
    .map(|w| f64::from_str(w))
    .filter(|r| r.is_ok())
    .map(|r| r.unwrap())


flat_map 的签名如下所示：

fn flat_map<U, F>(self, f: F) -> impl Iterator<Item = U::Item>
where
    F: FnMut(Self::Item) -> U,
    U: IntoIterator;


传递给 flat_map 的闭包对象必须返回一个可迭代的对象，不过任何类型的可迭代对象都可以使用。 1

例如，假设我们有一个表格，该表格将各国与其主要城市进行关联。现在给定一个国家列表，我们该如何遍历这些国家的主要城市呢？

use std::collections::HashMap;

let mut major_cities = HashMap::new();
major_cities.insert("Japan", vec!["Tokyo", "Kyoto"]);
major_cities.insert("The United States", vec!["Portland", "Nashville"]);
major_cities.insert("Brazil", vec!["São Paulo", "Brasília"]);
major_cities.insert("Kenya", vec!["Nairobi", "Mombasa"]);
major_cities.insert("The Netherlands", vec!["Amsterdam", "Utrecht"]);

let countries = ["Japan", "Brazil", "Kenya"];

for &city in countries.iter().flat_map(|country| &major_cities[country]) {
    println!("{city}");
}

这将输出如下内容：

Tokyo
Kyoto
São Paulo
Brasília
Nairobi
Mombasa


不过请注意，迭代器是“懒惰”的：只有 for 循环调用 flat_map 迭代器的 next 方法时，才会触发相应的操作。整个连接序列并不会在内存中构建起来。相反，这里存在一个小型的状态机，它依次从城市迭代器中获取一个元素，直到该迭代器耗尽为止，然后才会为下一个国家创建一个新的城市迭代器。这种实现方式类似于嵌套循环，但被包装成了迭代器的形式以供使用。

使变平


flatten 适配器会将迭代器的元素串联起来，假设每个元素本身也是一个可迭代对象。

use std::collections::BTreeMap;

// A table mapping cities to their parks: each value is a vector.
let mut parks = BTreeMap::new();
parks.insert("Portland",  vec!["Mt. Tabor Park", "Forest Park"]);
parks.insert("Kyoto",     vec!["Tadasu-no-Mori Forest", "Maruyama Koen"]);
parks.insert("Nashville", vec!["Percy Warner Park", "Dragon Park"]);

// Build a vector of all parks. `values` gives us an iterator producing
// vectors, and then `flatten` produces each vector's elements in turn.
let all_parks: Vec<_> = parks.values().flatten().cloned().collect();

assert_eq!(
    all_parks,
    vec![
        "Tadasu-no-Mori Forest", "Maruyama Koen", "Percy Warner Park",
        "Dragon Park", "Mt. Tabor Park", "Forest Park",
    ],
);


flatten 的签名如下：

fn flatten(self) -> impl Iterator<Item = <Self::Item as IntoIterator>::Item>
where
    Self::Item: IntoIterator;


flatten 方法有几种令人惊讶的使用方式。如果你有一个 Vec<Option<...>> ，并且只想遍历 Some 这些值，那么 flatten 的方法就非常适用：

assert_eq!(
    vec![None, Some("day"), None, Some("one")]
        .into_iter()
        .flatten()
        .collect::<Vec<_>>(),
    vec!["day", "one"],
);

之所以如此，是因为 Option 本身实现了 IntoIterator 的功能，这意味着它只能包含零个或一个或多个元素。 None 元素在迭代过程中并不产生任何影响，而每个 Some 元素则会贡献一个值。同样地，你也可以使用 flatten 来遍历 Option<Vec<...>> 个值： None 的行为类似于一个空向量。

Result 也实现了 IntoIterator 的功能，其中 Err 表示一个空序列。因此，对 Result 个值组成的迭代器应用 flatten 函数，实际上会筛选出所有的 Err 值并丢弃它们，最终得到只包含成功值的序列。我们不建议在代码中忽略错误，但这是一种人们在自以为了解情况时所使用的巧妙方法。

你可能会发现自己想要调用 flatten 这个函数，而实际上你需要的是 flat_map 这个函数。例如，标准库中的 str::to_uppercase 方法可以将字符串转换为大写形式，其运作方式大致如下：

fn to_uppercase(&self) -> String {
    self.chars()
        .map(char::to_uppercase)
        .flatten()  // there's a better way
        .collect()
}


之所以需要 flatten ，是因为 ch.to_uppercase() 不仅仅返回一个字符，而是一个能够生成一个或多个字符的迭代器。将每个字符映射到其大写形式后，就会得到一系列字符的迭代器。而 flatten 则负责将这些迭代器拼接在一起，最终形成一个我们可以进一步处理 String 的对象。


不过， map 和 flatten 的结合如此常见，以至于 Iterator 就提供了针对这种情况的 flat_map 适配器。实际上，在 flatten 被加入标准库之前， flat_map 就已经被纳入了标准库中了。因此，上述代码可以这样编写：

fn to_uppercase(&self) -> String {
    self.chars().flat_map(char::to_uppercase).collect()
}

持续获取


Iterator 特性中的 take 和 take_while 适配器允许你在处理一定数量的项目后结束迭代，或者当某个闭包决定停止处理时终止迭代。它们的签名如下：

fn take(self, n: usize) -> impl Iterator<Item = Self::Item>
where
    Self: Sized;

fn take_while<P>(self, predicate: P) -> impl Iterator<Item = Self::Item>
where
    Self: Sized,
    P: FnMut(&Self::Item) -> bool;


这两个迭代器都负责处理迭代器对象，并返回一个新的迭代器。这个新迭代器会继续传递来自第一个迭代器的数据，可能会提前结束序列的处理。 take 迭代器在生成最多 n 个数据后返回 None 。 take_while 迭代器会对每个数据应用 predicate 函数，并在每个调用 next 时返回 None ，其中对于第一个数据来说， predicate 返回 false ，而在后续每次调用 next 时，都会返回 None 。

例如，如果有一封电子邮件消息，其中标题与正文之间有一行空格分隔，那么可以使用 take_while 来仅遍历标题部分：

let message = "\
    To: jimb\r\n\
    From: superego <editor@oreilly.com>\r\n\
    \r\n\
    Did you get any writing done today?\r\n\
    When will you stop wasting time plotting fractals?\r\n";
for header in message.lines().take_while(|l| !l.is_empty()) {
    println!("{header}");
}


还记得在“字符串和字符字面量”部分提到的内容：当字符串中的一行以反斜杠结尾时，Rust 不会为下一行添加缩进，因此字符串中的每一行都没有前导空白字符。这意味着 message 这一行是空白的。而 take_while 适配器在看到空白行时就会终止迭代，所以这段代码只会打印出这两行内容：

To: jimb
From: superego <editor@oreilly.com>

跳过并继续循环


Iterator trait 的 skip 和 skip_while 方法相当于 take 和 take_while 方法的补充：它们在每次迭代开始时会移除一定数量的物品，或者一直移除物品直到找到一个可接受的解决方案，然后让剩余的物品保持不变。它们的签名如下：

fn skip(self, n: usize) -> impl Iterator<Item = Self::Item>
where
    Self: Sized;

fn skip_while<P>(self, predicate: P) -> impl Iterator<Item = Self::Item>
where
    Self: Sized,
    P: FnMut(&Self::Item) -> bool;


skip 适配器的一个常见用途是在遍历程序的命令行参数时，跳过命令名称。在第二章中，我们的“通用分母计算器”使用了以下代码来循环处理其命令行参数：

for arg in std::env::args().skip(1) {
    ...
}


std::env::args 函数返回一个迭代器，该迭代器将程序的参数作为 String 形式进行处理。其中第一个参数就是程序本身的名称。不过这个名称并不是我们需要进行处理的字符串。对那个迭代器调用 skip(1) 函数会返回一个新的迭代器，这个迭代器在第一次调用程序名称时会丢弃该名称，然后继续处理后续的参数。


skip_while 适配器通过一种机制来决定从序列的开头处丢弃多少个项。你可以像这样遍历前面部分消息中的正文行：

for body in message
    .lines()
    .skip_while(|l| !l.is_empty())
    .skip(1)
{
    println!("{body}");
}

这里使用了 skip_while 来跳过非空白的行，但那个迭代器确实产生了空白行——毕竟，该闭包为那一行返回了 false 。因此，我们也使用了 skip 方法来去除那行中的空白行，这样得到的迭代器中的第一个元素就是消息正文的第一行。结合前面章节中对 message 的声明，这段代码最终会输出如下内容：

Did you get any writing done today?
When will you stop wasting time plotting fractals?

可查看的


一种可预览的迭代器，允许你在不实际消耗下一个元素的情况下，预览下一个将要产生的元素。你可以通过调用 Iterator trait 的 peekable 方法来将任何迭代器转换为可预览的迭代器。

fn peekable(self) -> std::iter::Peekable<Self>
where
    Self: Sized;


在这里， Peekable<Self> 是一个实现了 Iterator<Item = Self::Item> 的 struct ，而 Self 则是底层迭代器的类型。


Peekable 类型的迭代器有一个额外的方法 peek ，该方法在底层迭代器结束时返回 Option<&Item> None ；如果迭代器尚未结束，则返回 Some(r) 。其中 r 是一个对下一个项的共享引用。（注意，如果迭代器的项类型本身就是一个引用，那么这种方法最终会变成一个引用本身的引用。）

调用 peek 会尝试从底层迭代器中获取下一个元素。如果有的话，会将其缓存起来，直到下次再次调用 next 。 Peekable 上所有其他 Iterator 方法都知道这个缓存机制：例如，在可窥视迭代器 iter 上调用 iter.last() 时，会在使用完底层迭代器后检查缓存中的内容。

当无法确定从迭代器中获取多少项时，Peekable 迭代器就非常有用。例如，在从字符流中解析数字时，在看到第一个非数字字符之前，你是无法确定数字的结束位置的。

use std::iter::Peekable;

fn parse_number<I>(tokens: &mut Peekable<I>) -> u32
where
    I: Iterator<Item = char>,
{
    let mut n = 0;
    loop {
        match tokens.peek() {
            Some(r) if r.is_digit(10) => {
                n = n * 10 + r.to_digit(10).unwrap();
            }
            _ => return n,
        }
        tokens.next();
    }
}

let mut chars = "226153980,1766319049".chars().peekable();
assert_eq!(parse_number(&mut chars), 226153980);
// Look, `parse_number` didn't consume the comma! So we will.
assert_eq!(chars.next(), Some(','));
assert_eq!(parse_number(&mut chars), 1766319049);
assert_eq!(chars.next(), None);


parse_number 函数使用 peek 来检查下一个字符，并且只有当该字符为数字时才会处理它。如果字符不是数字，或者迭代器已经耗尽（即 peek 返回了 None ），那么我们就会返回已解析的数字，并将下一个字符保留在迭代器中，以便后续处理。

保险丝


fuse 适配器可以接受任何迭代器，并生成一个这样的迭代器：在第一次调用后，该迭代器会持续返回 None 。

struct Flaky(bool);

impl Iterator for Flaky {
    type Item = &'static str;
    fn next(&mut self) -> Option<Self::Item> {
        if self.0 {
            self.0 = false;
            Some("totally the last item")
        } else {
            self.0 = true;  // D'oh!
            None
        }
    }
}

let mut flaky = Flaky(true);
assert_eq!(flaky.next(), Some("totally the last item"));
assert_eq!(flaky.next(), None);
assert_eq!(flaky.next(), Some("totally the last item"));

let mut not_flaky = Flaky(true).fuse();
assert_eq!(not_flaky.next(), Some("totally the last item"));
assert_eq!(not_flaky.next(), None);
assert_eq!(not_flaky.next(), None);


fuse 适配器在那些需要处理来源不确定的迭代器的通用代码中最为实用。与其担心会遇到所有不规范的迭代器，不如使用 fuse 来确保一切正常。

可逆迭代器与反向迭代


一些迭代器能够从序列的任意一端提取元素。可以通过使用 rev 适配器来反转这些迭代器。例如，一个用于向量上的迭代器，既可以从向量的末尾提取元素，也可以从开头提取元素。这样的迭代器可以实现 std::iter::DoubleEndedIterator 特征，该特征扩展了 Iterator 的功能。

trait DoubleEndedIterator: Iterator {
    fn next_back(&mut self) -> Option<Self::Item>;
}

你可以将双端迭代器想象成有两个“手指”，分别指向序列的当前开头和结尾。从任一端提取元素都会使相应的“手指”向另一端移动；当这两根“手指”相遇时，迭代就完成了。

let bee_parts = ["head", "thorax", "abdomen"];

let mut iter = bee_parts.iter();
assert_eq!(iter.next(),      Some(&"head"));
assert_eq!(iter.next_back(), Some(&"abdomen"));
assert_eq!(iter.next(),      Some(&"thorax"));

assert_eq!(iter.next_back(), None);
assert_eq!(iter.next(),      None);

对切片进行迭代时，这种结构使得实现这种行为变得简单：实际上，只需要两个指针分别指向尚未生成的元素范围的起始点和终点； next 和 next_back 分别指向这些范围的起始点和终点。对于像 BTreeSet 和 BTreeMap 这样的有序集合，其迭代器也是双端结构的：它们的 next_back 方法会优先显示最大的元素或条目。一般来说，标准库会在适当的情况下提供双端迭代功能。

但是，并非所有的迭代器都能如此轻松地执行此操作：那些来自其他线程、通过通道 Receiver 传递值的迭代器，无法预知最后一个接收到的数值是什么。通常，你需要查阅标准库的文档，以了解哪些迭代器实现了 DoubleEndedIterator 功能，哪些则没有。

如果迭代器的操作范围是可以双向进行的，那么你可以使用 rev 适配器来反转它。

fn rev(self) -> impl Iterator<Item = Self>
where
    Self: Sized + DoubleEndedIterator;

返回的迭代器也是双端迭代器：它的 next 和 next_back 方法只是名称互换而已。

let meals = ["breakfast", "lunch", "dinner"];

let mut iter = meals.iter().rev();
assert_eq!(iter.next(), Some(&"dinner"));
assert_eq!(iter.next_back(), Some(&"breakfast"));
assert_eq!(iter.next(), Some(&"lunch"));
assert_eq!(iter.next_back(), None);


大多数迭代器适配器，当应用于可逆迭代器时，都会返回另一个可逆迭代器。例如， map 和 filter 都具备可逆性。

检查


inspect 适配器在调试迭代器适配器系列时非常有用，但在生产代码中很少被使用。它只是将一个闭包应用于每个共享引用上，然后继续传递该元素。这个闭包不会影响元素本身，但可以用来执行诸如打印元素或对其进行断言之类的操作。

这个例子展示了将字符串转换为大写后，其长度会发生变化的情形：

let upper_case: String = "große"
    .chars()
    .inspect(|c| println!("before: {c:?}"))
    .flat_map(|c| c.to_uppercase())
    .inspect(|c| println!(" after:     {c:?}"))
    .collect();
assert_eq!(upper_case, "GROSSE");

德语小写字母“ß”的大写形式是“SS”。因此，当使用 char::to_uppercase 时，它会返回一个字符迭代器，而不是一个单独替换字符。上述代码中，使用 flat_map 来连接 to_uppercase 返回的所有序列，然后将它们合并到一个 String 中，最终打印出如下结果：

before: 'g'
 after:     'G'
before: 'r'
 after:     'R'
before: 'o'
 after:     'O'
before: 'ß'
 after:     'S'
 after:     'S'
before: 'e'
 after:     'E'

链条


chain 适配器将一个迭代器附加到另一个之后。更准确地说， i1.chain(i2) 返回一个迭代器，该迭代器会从 i1 开始提取元素，直到耗尽资源后，才会继续从 i2 开始提取元素。


chain 适配器的签名如下：

fn chain<U>(self, other: U) -> impl Iterator<Item = Self::Item>
where
    Self: Sized,
    U: IntoIterator<Item = Self::Item>;

换句话说，你可以将任何能够产生相同类型数据的可迭代对象串联起来，形成一个迭代器。

例如：

let v: Vec<i32> = (1..4).chain([20, 30, 40]).collect();
assert_eq!(v, [1, 2, 3, 20, 30, 40]);

如果一个 chain 迭代器的两个底层迭代器都是可逆的，那么这个 chain 迭代器也是可逆的。

let v: Vec<i32> = (1..4).chain([20, 30, 40]).rev().collect();
assert_eq!(v, [40, 30, 20, 3, 2, 1]);


一个 chain 迭代器能够跟踪两个底层迭代器是否都已经返回了 None 值。然后，它会根据具体情况指导 next 和 next_back 分别调用其中一个迭代器。

列举


Iterator 特征中的 enumerate 适配器会在序列上添加一个运行索引，它接受一个生成单个元素的迭代器，并返回一个生成成对元素的迭代器。乍看之下似乎很简单，但实际上这种实现被频繁地使用着。


消费者可以利用这个索引来区分不同的项目，并确定处理每个项目的上下文。例如，第 2 章中的 Mandelbrot 集绘图工具将图像划分为八条水平条带，并让每个条带对应到一个不同的线程。这段代码使用 enumerate 来表示每个线程所负责的图像中的哪一条条带。

这一切都始于一个矩形的像素缓冲区：

let mut pixels = vec![0; columns * rows];

接下来，它使用 chunks_mut 来将图像分割成多个水平条带，每个线程负责处理一个条带。

let rows_per_band = rows.div_ceil(threads);
...
let bands = pixels.chunks_mut(rows_per_band * columns);

然后，它会遍历各个频段，为每个频段分别创建一个线程：

for (i, band) in bands.enumerate() {
    let top = rows_per_band * i;
    // start a thread to render rows `top..top + band_rows`
    ...
}

每次迭代都会获得一对数据 (i, band) ，其中 band 是线程应该绘制的像素缓冲区的 &mut [u8] 切片，而 i 则是该区域在整幅图像中的索引。这些信息由 enumerate 适配器提供。根据图表的边界以及各条带的宽度，这些信息足以让线程确定自己被分配到图像的哪个部分，从而决定向 band 输出哪些图像数据。

你可以将 enumerate 产生的 (index, item) 对，视为在遍历 HashMap 或其他关联集合时得到的 (key, value) 对。如果你是在遍历一个切片或向量，那么 index 就是 item 出现的“键”。

zip


zip 适配器将两个迭代器合并为一个单一的迭代器，这个迭代器会生成若干对元素，每对元素来自其中一个迭代器，就像拉链将两片拉链连接在一起一样。当任意一个底层迭代器结束时，这个合并后的迭代器也会停止工作。


例如，你可以通过对无限制范围的 0.. 进行压缩处理，然后将其与另一个迭代器结合使用，从而达到与 enumerate 适配器相同的效果。

let v: Vec<_> = (0..).zip("ABCD".chars()).collect();
assert_eq!(v, vec![(0, 'A'), (1, 'B'), (2, 'C'), (3, 'D')]);

从这个意义上说，你可以将 zip 视为 enumerate 的泛化版本：虽然 enumerate 是向序列添加索引，但 zip 则是向任意迭代器的元素添加索引。之前我们已经提到过， enumerate 可以帮助提供处理元素的上下文；而 zip 则是实现这一功能的更灵活方式。

传递给 zip 的参数不必是迭代器；它可以是任何可迭代对象：

use std::iter;

let endings = ["once", "twice", "chicken soup with rice"];
let rhyme: Vec<_> = iter::repeat("going")
    .zip(endings)
    .collect();
assert_eq!(
    rhyme,
    vec![
        ("going", "once"),
        ("going", "twice"),
        ("going", "chicken soup with rice"),
    ],
);

by_ref


迭代器的 by_ref 方法会借用一个可变的引用对象，这样你就可以对这些引用对象应用适配器了。当你不再需要这些适配器时，就可以释放对借用的引用，然后恢复对原始迭代器的访问。


例如，在本章的开头部分，我们展示了如何使用 take_while 和 skip_while 来处理邮件的头部信息和正文内容。但是，如果你希望同时处理这两部分内容，可以使用同一个迭代器。通过 by_ref 来处理头部信息，之后再回到原始的迭代器上，而 take_while 则可以在正确的位置继续处理正文内容。

let message = "\
    To: jimb\r\n\
    From: id\r\n\
    \r\n\
    Oooooh, donuts!!\r\n";

let mut lines = message.lines();

println!("Headers:");
for header in lines.by_ref().take_while(|l| !l.is_empty()) {
    println!("{header}");
}

println!("\nBody:");
for body in lines {
    println!("{body}");
}

调用 lines.by_ref() 会借用一个可变的迭代器引用，而 take_while 迭代器则拥有该引用。这个迭代器会在第一个 for 循环结束时超出作用域，这意味着借用操作已经结束。因此，你可以在第二个 for 循环中再次使用 lines 。这样就能输出如下结果：

Headers:
To: jimb
From: id

Body:
Oooooh, donuts!!


by_ref 适配器的定义相当简单：它返回一个可变的迭代器引用。此外，标准库还提供了这个奇特的实现方式：

impl<I: Iterator + ?Sized> Iterator for &mut I {
    type Item = I::Item;
    fn next(&mut self) -> Option<I::Item> {
        (**self).next()
    }
    ...
}


换句话说，如果 I 是某种迭代器类型，那么 &mut I 同样也是一个迭代器，其 next 方法会调用其引用对象的相应方法。当对迭代器的可变引用对象调用适配器时，适配器会取得该引用的所有权，而不是迭代器本身。这种借用仅在适配器超出作用域时终止。

复制的，仿制的


cloned 适配器接受一个生成引用的迭代器，并返回一个生成从这些引用克隆出的值的迭代器，这与 iter.map(|item| item.clone()) 的功能类似。当然，该引用类型必须实现 Clone 接口。例如：

let a = ['1', '2', '3', '∞'];

assert_eq!(a.iter().next(),          Some(&'1'));
assert_eq!(a.iter().cloned().next(), Some('1'));


copied 适配器也是基于同样的思路，但更加严格：被引用类型必须实现 Copy 。类似 iter.copied() 这样的调用，本质上与 iter.map(|r| *r) 是相同的。由于所有实现 Copy 的类型也都实现了 Clone ，因此 cloned 的通用性更强。不过，具体取决于项目类型， clone 的调用可以进行任意数量的分配和复制操作。如果你认为这种情况永远不会发生，因为你的项目类型很简单，那么最好使用 copied 来让类型检查器验证你的假设是否正确。

循环


cycle 适配器返回一个迭代器，该迭代器不断重复由底层迭代器产生的序列。底层迭代器必须实现 std::clone::Clone 接口，这样 cycle 就可以保存其初始状态，并在每次循环开始时重新使用这些状态。

例如：

let dirs = ["North", "East", "South", "West"];
let mut spin = dirs.iter().cycle();
assert_eq!(spin.next(), Some(&"North"));
assert_eq!(spin.next(), Some(&"East"));
assert_eq!(spin.next(), Some(&"South"));
assert_eq!(spin.next(), Some(&"West"));
assert_eq!(spin.next(), Some(&"North"));
assert_eq!(spin.next(), Some(&"East"));

或者，对于迭代器的那种完全无必要的使用来说：

use std::iter;

let fizzes = iter::repeat_n("", 2).chain(iter::once("fizz")).cycle();
let buzzes = iter::repeat_n("", 4).chain(iter::once("buzz")).cycle();
let fizzes_buzzes = fizzes.zip(buzzes);

let fizz_buzz = (1..100)
    .zip(fizzes_buzzes)
    .map(|tuple| match tuple {
        (i, ("", "")) => i.to_string(),
        (_, (fizz, buzz)) => format!("{fizz}{buzz}"),
    });

for line in fizz_buzz {
    println!("{line}");
}


这是一个儿童文字游戏，现在有时也被用作程序员面试中的问题。在游戏中，玩家轮流计数，将所有能被 3 整除的数字替换为“ fizz ”，将所有能被 5 整除的数字替换为“ buzz ”。同时，那些能被 3 和 5 整除的数字则被替换为“ fizzbuzz ”。

消耗迭代器


到目前为止，我们已经学习了如何创建迭代器，以及如何将其改造为新的迭代器。现在，我们将结束这个过程，介绍一些使用这些迭代器的方法。

当然，你可以通过 for 循环来使用迭代器，或者直接调用 next 函数。但是，有许多常见的任务是不需要反复编写的。 Iterator 特质提供了一系列方法，可以解决这些常见问题。

简单积累：计数、求和、求积


count 方法会从迭代器中提取元素，直到返回 None ，并告知它提取了多少个元素。下面是一个简单的程序，用于计算字符串中英语元音字母的数量：

const VOWELS: [char; 5] = ['A', 'E', 'I', 'O', 'U'];

fn count_vowels(s: &str) -> usize {
    s.to_uppercase()
        .chars()
        .filter(|c| VOWELS.contains(c))
        .count()
}


sum 和 product 方法用于计算迭代器所包含元素的求和或乘积，这些元素必须是整数或浮点数形式：

fn triangle(n: u64) -> u64 {
    (1..=n).sum()
}
assert_eq!(triangle(20), 210);

fn factorial(n: u64) -> u64 {
    (1..=n).product()
}
assert_eq!(factorial(20), 2432902008176640000);

你可以通过实现 std::iter::Sum 和 std::iter::Product 这些特性，使得 sum 和 product 能够适用于其他类型的数据。不过，关于这些特性的具体实现细节，本书并不会进行描述。

最大值、最小值


在 Iterator 上的 min 和 max 方法分别返回迭代器产生的其中最小或最大的元素。迭代器的元素类型必须实现 std::cmp::Ord 接口，这样就能对元素进行比较。例如：

assert_eq!([-2, 0, 1, 0, -2, -5].iter().max(), Some(&1));
assert_eq!([-2, 0, 1, 0, -2, -5].iter().min(), Some(&-5));


如“有序比较”部分所解释的，Rust 的浮点类型 f32 和 f64 仅实现了 std::cmp::PartialOrd 的功能，而并非 std::cmp::Ord 的功能。因此，无法使用 min 和 max 方法来找出一系列浮点数中的最小或最大数。这并非 Rust 设计的常见特性，但这是有意为之：目前还不清楚这类函数在处理 IEEE NaN 值时会产生什么效果。直接忽略这些值可能会导致代码中出现更严重的问题。


如果你知道希望如何处理 NaN 值，可以使用 max_by 和 min_by 这些迭代方法，它们允许你提供自己的比较函数。

最大值：max_by 最小值：min_by


max_by 和 min_by 方法会根据您提供的比较函数，返回迭代器所产生的最大或最小元素。

use std::cmp::Ordering;

// Compare two f64 values. Panic if given a NaN.
fn cmp(lhs: &f64, rhs: &f64) -> Ordering {
    lhs.partial_cmp(rhs).unwrap()
}

let numbers = [1.0, 4.0, 2.0];
assert_eq!(numbers.iter().copied().max_by(cmp), Some(4.0));
assert_eq!(numbers.iter().copied().min_by(cmp), Some(1.0));

let numbers = [1.0, 4.0, f64::NAN, 2.0];
assert_eq!(numbers.iter().copied().max_by(cmp), Some(4.0));  // panics


max_by 和 min_by 方法通过引用将参数传递给比较函数，这样它们就可以高效地与任何类型的迭代器一起使用。因此， cmp 期望以引用方式接收其参数，尽管我们使用了 copied 来创建一个能够生成 f64 个元素的迭代器。

max_by_key, min_by_key


在 Iterator 中的 max_by_key 和 min_by_key 方法允许你根据应用于每个元素的闭包来选择最大或最小的元素。这个闭包可以选择元素的某个字段，或者对元素进行运算。因为人们通常关心的是与某个最小值或最大值相关的数据，而不仅仅是极值本身，所以这些函数通常比 min 和 max 更有用。它们的签名如下：

fn min_by_key<B: Ord, F>(self, f: F) -> Option<Self::Item>
where
    Self: Sized,
    F: FnMut(&Self::Item) -> B;

fn max_by_key<B: Ord, F>(self, f: F) -> Option<Self::Item>
where
    Self: Sized,
    F: FnMut(&Self::Item) -> B;


也就是说，给定一个闭包，该闭包接受一个参数并返回任何有序类型 B 。那么应该返回那个被闭包返回最大值或最小值的参数 B ，如果没有任何参数被产生，则返回 None 。

例如，如果你需要扫描一个城市哈希表，以找出人口最多和最少的城市，你可以这样编写代码：

use std::collections::HashMap;

let mut populations = HashMap::new();
populations.insert("Portland",  583_776);
populations.insert("Fossil",        449);
populations.insert("Greenhorn",       2);
populations.insert("Boring",      7_762);
populations.insert("The Dalles", 15_340);

assert_eq!(
    populations.iter().max_by_key(|&(_name, pop)| pop),
    Some((&"Portland", &583_776)),
);
assert_eq!(
    populations.iter().min_by_key(|&(_name, pop)| pop),
    Some((&"Greenhorn", &2)),
);


这个闭包应用于迭代器产生的每个项目，并返回用于比较的值——在这种情况下，就是该城市的人口数量。返回的值是整个项目本身，而不仅仅是闭包所返回的值。（当然，如果你经常需要执行这样的查询，那么最好找到一种更高效的方式来查找条目，而不是通过线性搜索整个表格。）

比较项目序列


你可以使用 < 和 == 运算符来比较字符串、向量和切片，前提是这些元素的个体是可以进行比较的。虽然迭代器不支持 Rust 中的比较运算符，但它们提供了类似 eq 和 lt 的方法，这些方法可以从迭代器中取出成对的元素进行比较，直到得出最终结论。例如：

let packed =  "Helen of Troy";
let spaced =  "Helen   of    Troy";
let obscure = "Helen of Sandusky";  // nice person, just not famous

assert!(packed != spaced);
assert!(packed.split_whitespace().eq(spaced.split_whitespace()));

// This is true because ' ' < 'o'.
assert!(spaced < obscure);

// This is true because "Troy" > "Sandusky".
assert!(spaced.split_whitespace().gt(obscure.split_whitespace()));

对 split_whitespace 的调用会返回字符串中由空格分隔的单词的迭代器。使用 eq 和 gt 方法对这些迭代器进行操作时，可以进行逐单词的比较，而不是逐字符的比较。之所以可以实现这种比较，是因为 &str 实现了 PartialOrd 和 PartialEq 的功能。

迭代器提供了 eq 和 ne 方法用于相等性比较，而 lt 、 le 、 gt 和 ge 方法则用于有序比较。 cmp 和 partial_cmp 方法的行为类似于 Ord 和 PartialOrd 特质中对应的方法。

所有情况


any 和 all 方法会对迭代器产生的每个项施加一个闭包操作。如果对于任何一个项，或者对于所有的项来说，该闭包返回 true 的值，那么就会返回 true 。

let id = "Iterator";

assert!( id.chars().any(char::is_uppercase));
assert!(!id.chars().all(char::is_uppercase));

这些方法在计算出结果时，只会使用与计算所需数量相同的元素。例如，如果某个元素始终返回 true ，那么 any 会立即返回 true ，而不会再从迭代器中读取更多元素。

position、rposition 以及 ExactSizeIterator


position 方法会对迭代器中的每个元素应用一个闭包函数，并返回第一个满足闭包函数返回 true 的元素的索引。更准确地说，它返回的是索引的 Option 值：如果没有任何元素满足闭包函数的条件，则返回 position ；而当闭包函数返回 true 时，绘制就会停止。例如：

let text = "Xerxes";
assert_eq!(text.chars().position(|c| c == 'e'), Some(1));
assert_eq!(text.chars().position(|c| c == 'z'), None);


rposition 该方法也是一样的，只不过它的搜索方向是从右往左。例如：

let bytes = b"Xerxes";
assert_eq!(bytes.iter().rposition(|&c| c == b'e'), Some(4));
assert_eq!(bytes.iter().rposition(|&c| c == b'X'), Some(0));


rposition 方法需要一个可反转的迭代器，这样它才能从序列的右端开始提取元素。此外，还需要一个精确大小的迭代器，以便能够以与 position 相同的方式分配索引，从左侧的 0 开始。精确大小的迭代器是指实现了 std::iter::ExactSizeIterator 特征的类。

trait ExactSizeIterator: Iterator {
    fn len(&self) -> usize { ... }
    fn is_empty(&self) -> bool { ... }
}


len 方法返回剩余的项目数量，而 is_empty 方法在迭代完成时会返回 true 。

当然，并不是每个迭代器都能提前知道自己会生成多少项。例如，之前使用的 str::chars 迭代器是无法知道具体会生成多少项的（因为 UTF-8 是一种可变宽度的编码方式），所以你不能在字符串上使用 rposition 。但是，一个用于字节数组的迭代器肯定知道数组的长度，因此它可以实现 ExactSizeIterator 的功能。

折叠与递归折叠


fold 方法是一个非常通用的工具，可以用于累积迭代器产生的所有项的结果。首先给定一个初始值，我们将其称为累积器，然后有一个闭包 fold 。该闭包会反复应用于当前的累积器以及迭代器下的下一个项。闭包返回的值被作为新的累积器，随后会被传递给闭包以处理下一个项。最终的累积器值就是 fold 所返回的结果。如果序列为空，那么 fold simply 会返回初始的累积器值。

其他许多用于获取迭代器值的方法都可以表示为对 fold 的调用：

let a = [5, 6, 7, 8, 9, 10];

assert_eq!(a.iter().fold(0, |n, _| n + 1), 6);       // count
assert_eq!(a.iter().fold(0, |n, i| n + i), 45);      // sum
assert_eq!(a.iter().fold(1, |n, i| n * i), 151200);  // product

// max
assert_eq!(
    a.iter().cloned().fold(i32::min_value(), std::cmp::max),
    10,
);


fold 方法的签名如下：

fn fold<A, F>(self, init: A, f: F) -> A
where
    Self: Sized,
    F: FnMut(A, Self::Item) -> A;

在这里， A 表示累加器类型。 init 参数是一个 A ，同样，闭包的第一个参数和返回值也是 A 类型，而 fold 本身的返回值也是 A 类型。

请注意，累加器的值会被移动到闭包中，然后再次取出。因此，你可以将 fold 用于非 Copy 类型的累加器操作中。

let a = ["Pack", "my", "box", "with", "five", "dozen", "liquor", "jugs"];

// See also: the `join` method on slices, which won't
// give you that extra space at the end.
let pangram = a.iter().fold(String::new(), |s, w| s + w + " ");
assert_eq!(pangram, "Pack my box with five dozen liquor jugs ");


rfold 方法与 fold 方法相同，不过它需要一个双端迭代器作为参数，并且会按照从后到前的顺序来处理其接收到的元素。

let weird_pangram = a.iter().rfold(String::new(), |s, w| s + w + " ");
assert_eq!(weird_pangram, "jugs liquor dozen five with box my Pack ");

try_fold 和 try_rfold


try_fold 方法与 fold 方法相同，不过 try_fold允许在迭代过程中提前终止，而不会消耗迭代器中的所有值。你传递给 try_fold 的闭包函数所返回的值，决定了它应该是立即返回，还是继续处理迭代器中的元素。


你的关闭操作可以返回多种类型的结果，这些结果决定了折叠过程的进行方式：

  • 如果您的闭包返回 Result<T, E> ，可能是因为它进行了 I/O 操作或执行了某些可能出错的操作，那么返回 Ok(v) 就会告诉 try_fold 继续折叠操作，而 v 则成为新的累加值。返回 Err(e) 则会立即停止折叠操作。折叠操作的最终结果是一个 Result ，它包含了最终的累加值，或者就是闭包返回的错误值。

  • 如果您的关闭操作返回 Option<T> ，那么 Some(v) 表示折叠应继续，将 v 作为新的累积值；而 None 则表示迭代应立即停止。折叠的最终值也是一个 Option 。


  • 最后，该闭包可以返回一个 std::ops::ControlFlow 类型的值。这个类型是一个枚举，包含两种变体： Continue(c) 和 Break(b) 。这意味着要么继续使用新的累加值 c ，要么提前停止。如果闭包返回了某个值，那么折叠的结果就是 ControlFlow 类型的值： Continue(v) ；否则，结果就是 Break(b) 。

    Continue(c) 和 Break(b) 的行为与 Ok(c) 和 Err(b) 完全一样。使用 ControlFlow 而不是 Result 的优势在于，当提前退出时，代码会显得更易于理解，因为此时并不表示出现了错误，而只是说明答案已经提前准备好了。下面我们举了一个例子来说明这一点。

这是一个能够计算从标准输入中读取的数字之和的程序：

use std::error::Error;
use std::str::FromStr;

fn main() -> Result<(), Box<dyn Error>> {
    let sum = std::io::stdin()
        .lines()
        .try_fold(0, |sum, line| -> Result<u64, Box<dyn Error>> {
            Ok(sum + u64::from_str(line?.trim())?)
        })?;
    println!("{sum}");
    Ok(())
}


在带有缓冲的输入流上， lines 迭代器会返回 Result<String, std::io::Error> 类型的元素；而将 String 解析为整数的操作也可能失败。在这里使用 try_fold 可以让闭包返回 Result<u64, ...> ，这样我们就可以使用 ? 操作符将失败情况从闭包传递到 main 函数。

因为 try_fold 具有极高的灵活性，所以它常被用来实现 Iterator 中的许多其他功能。例如，以下是 all 的一个实现示例：

fn all<P>(&mut self, mut predicate: P) -> bool
where
    Self: Sized,
    P: FnMut(Self::Item) -> bool,
{
    use std::ops::ControlFlow::*;
    self.try_fold((), |_, item| {
        if predicate(item) { Continue(()) } else { Break(()) }
    }) == Continue(())
}


如果你正在自己实现一种迭代器类，那么值得探讨的是：你的迭代器是否能够比 Iterator trait 提供的默认实现更高效地完成相关操作。如果你能够提升 try_fold 的运行速度，那么基于它的所有其他方法也会得到相应的好处。


正如其名称所示， try_rfold 方法与 try_fold 方法是相同的。两者的区别在于， try_rfold 方法从后端获取值，而不是从前端获取，并且需要一个双端迭代器来使用。

第 n 个，第 n 个背靠


nth 方法接受一个索引 n ，从迭代器中跳过该数量的元素，然后返回下一个元素。如果序列在之前的位置结束，则返回 None 。调用 .nth(0) 相当于调用 .next() 。

它不会像适配器那样拥有迭代器的所有权，因此你可以多次调用它。

let mut squares = (0..10).map(|i| i * i);

assert_eq!(squares.nth(4), Some(16));
assert_eq!(squares.nth(0), Some(25));
assert_eq!(squares.nth(6), None);

其标志如下所示：

fn nth(&mut self, n: usize) -> Option<Self::Item>
where
    Self: Sized;


nth_back 方法的工作原理类似，只不过它是从双端迭代器的末尾进行取值。调用 .nth_back(0) 相当于调用 .next_back() ：它返回最后一个元素，如果迭代器为空，则返回 None 。

最后


last 方法返回迭代器产生的最后一个项，如果迭代器为空，则返回 None 。其签名如下：

fn last(self) -> Option<Self::Item>;

例如：

let squares = (0..10).map(|i| i * i);
assert_eq!(squares.last(), Some(81));

这会消耗掉迭代器从开始位置起的所有元素，即使该迭代器是可逆的。如果你有一个可逆的迭代器，而并不需要消耗其所有元素，那么可以直接使用 iter.next_back() 来表示省略这些元素。

find、rfind 和 find_map


find 方法从迭代器中提取元素，返回第一个满足给定闭包条件的元素。如果找不到合适的元素，该方法会返回 true 或 None 。其签名如下：

fn find<P>(&mut self, predicate: P) -> Option<Self::Item>
where
    Self: Sized,
    P: FnMut(&Self::Item) -> bool;


rfind 方法类似，但它需要一个双端迭代器。该方法从后往前搜索值，最终返回闭包所返回的最后一个元素。


例如，可以使用“max_by_key, min_by_key”中的城市及人口数据表，来编写如下代码：

assert_eq!(
    populations.iter().find(|&(_name, &pop)| pop > 1_000_000),
    None,
);
assert_eq!(
    populations.iter().find(|&(_name, &pop)| pop > 500_000),
    Some((&"Portland", &583_776)),
);


有时候，你的闭合操作并不只是对每一个元素进行简单的布尔判断然后继续处理下去：它可能是某种更复杂的操作，能够产生一个有趣的结果。在这种情况下， find_map 正是你所需要的工具。它的签名如下：

fn find_map<B, F>(&mut self, f: F) -> Option<B>
where
    F: FnMut(Self::Item) -> Option<B>;

这跟 find 的情况很像，只不过，这个闭包不是返回 bool ，而是应该返回某个 Option 的值。 find_map 则返回第一个满足 Some 条件的 Option 。

例如，如果我们有一个包含各个城市公园信息的数据库，我们可能会想查看其中是否有火山，如果有火山的话，还希望知道公园的名称。

let big_city_with_volcano_park = populations
    .iter()
    .find_map(|(&city, _)| {
        if let Some(park) = find_volcano_park(city, &parks) {
            // find_map returns this value, so our caller knows
            // *which* park we found.
            return Some((city, park.name));
        }

        // Reject this item, and continue the search.
        None
    });

assert_eq!(big_city_with_volcano_park, Some(("Portland", "Mt. Tabor Park")));

构建收藏集：从 Iterator 对象开始收集元素。


在整本书中，我们一直使用 collect 方法来构建包含迭代器元素的向量。例如，在第二章中，我们调用了 std::env::args() 来获取程序中命令行参数的迭代器，然后调用该迭代器的 collect 方法来将这些参数收集到向量中。

let args: Vec<String> = std::env::args().collect();

不过， collect 并不只适用于向量类型；实际上，它可以从 Rust 的标准库中提取任何类型的集合，只要迭代器能够产生合适的数据项类型即可。

use std::collections::{HashSet, BTreeSet, LinkedList, HashMap, BTreeMap};

let args: HashSet<String> = std::env::args().collect();
let args: BTreeSet<String> = std::env::args().collect();
let args: LinkedList<String> = std::env::args().collect();

// Collecting a map requires (key, value) pairs, so for this example,
// zip the sequence of strings with a sequence of integers.
let args: HashMap<String, usize> = std::env::args().zip(0..).collect();
let args: BTreeMap<String, usize> = std::env::args().zip(0..).collect();

// and so on


当然， collect 本身并不知道如何构造所有这些类型。相反，当像 Vec 或 HashMap 这样的集合类型知道如何从一个迭代器来构造自己时，它会实现 std::iter::FromIterator 特性。而 collect 只不过是一个方便使用的包装层而已。

trait FromIterator<A>: Sized {
    fn from_iter<T: IntoIterator<Item = A>>(iter: T) -> Self;
}

如果某个集合类型实现了 FromIterator<A> 接口，那么它的相关函数 from_iter 就能够从一个可迭代对象中提取出类型为 A 的元素，并构建出一个属于该类型的对象。

在最简单的情况下，实现方式可以是创建一个空集合，然后逐个添加迭代器中的元素。例如， std::collections::LinkedList 对 FromIterator 的实现就是采用这种方式的。

不过，有些类型的表现甚至更出色。例如，从某个迭代器 iter 构建向量可以如此简单：

let mut vec = Vec::new();
for item in iter {
    vec.push(item);
}
vec

但这种情况并不理想：随着向量的长度增加，可能需要扩展其缓冲区，这就需要调用堆分配器，并且需要复制现有的元素。虽然向量在算法层面会尽量减少这种开销，但如果能够有一种方法在初始化时就分配适当大小的缓冲区，那么就不必再进行尺寸调整了。

这就是 Iterator trait 中的 size_hint 方法发挥作用的地方：

trait Iterator {
    ...
    fn size_hint(&self) -> (usize, Option<usize>) {
        (0, None)
    }
}


这些限制信息正是 Vec 的实现在初始化新向量的缓冲区时需要获取的。插入操作仍然会检查缓冲区的容量是否足够，因此即使提示信息不准确，也只会影响性能，而不会影响到安全性。其他类型也可以采取类似的策略：例如， HashSet 和 HashMap 也会使用 Iterator::size_hint 来为他们的哈希表选择适当的初始容量。

关于类型推断的一点说明：在这一部分的顶部，看到同一个调用 std::env::args().collect() 根据上下文产生四种不同的集合类型，有点奇怪。 collect 的返回类型是其类型参数，因此前两次调用相当于以下这种形式：

let args = std::env::args().collect::<Vec<String>>();
let args = std::env::args().collect::<HashSet<String>>();


但是，只要存在一种可能作为 collect 参数的类型，Rust 的类型推断系统就会为你提供该类型。当你明确指定 args 的类型时，就确保了这一点。

扩展特性


如果一个类型实现了 std::iter::Extend trait，那么它的 extend 方法会将可迭代对象的元素添加到集合中：

let mut v: Vec<i32> = (0..5).map(|i| 1 << i).collect();
v.extend([31, 57, 99, 163]);
assert_eq!(v, [1, 2, 4, 8, 16, 31, 57, 99, 163]);

所有标准集合都实现了 Extend 方法，所以它们都有这个方法； String 也是如此。而数组和切片则具有固定长度，因此没有这个方法。

该特征的定义如下：

trait Extend<A> {
    fn extend<T>(&mut self, iter: T)
    where
        T: IntoIterator<Item = A>;
}


显然，这与 std::iter::FromIterator 的做法非常相似： std::iter::FromIterator 会创建一个新的集合，而 Extend 则是对已有集合的扩展。实际上，标准库中的 FromIterator 实现通常都是先创建一个新的空集合，然后再调用 extend 来填充该集合。例如， FromIterator 对 std::collections::LinkedList 的实现就是这么工作的：

impl<T> FromIterator<T> for LinkedList<T> {
    fn from_iter<I: IntoIterator<Item = T>>(iter: I) -> Self {
        let mut list = Self::new();
        list.extend(iter);
        list
    }
}

分割


partition 方法将一个迭代器的元素分配到两个集合中，而具体的分配方式则通过闭包来决定：每个元素应该属于哪个集合。

let things = ["doorknob", "mushroom", "noodle", "giraffe", "grapefruit"];

// Amazing fact: the name of a living thing always starts with an
// odd-numbered letter.
let (living, nonliving): (Vec<&str>, Vec<&str>) =
    things.iter().partition(|name| name.as_bytes()[0] & 1 != 0);

assert_eq!(living,    vec!["mushroom", "giraffe", "grapefruit"]);
assert_eq!(nonliving, vec!["doorknob", "noodle"]);


就像 collect 一样， partition 也可以创建你喜欢的任何类型的集合，不过两者必须是同一类型。而像 collect 那样，你还需要指定返回类型：上面的例子展示了 living 和 nonliving 的类型，并让类型推断为调用 partition 时选择合适的类型参数。


partition 的签名如下：

fn partition<B, F>(self, f: F) -> (B, B)
where
    Self: Sized,
    B: Default + Extend<Self::Item>,
    F: FnMut(&Self::Item) -> bool;


由于 collect 要求其结果类型实现 FromIterator 的功能，而 partition 则要求实现 std::default::Default 的功能。实际上，所有 Rust 中的集合类型都通过返回空集合来实现 std::default::Default 的功能，而 std::iter::Extend 也是如此。

其他语言提供了 partition 操作，该操作只是将迭代器拆分为两个迭代器，而无需创建两个集合。不过，这种做法并不适合在 Rust 中实现：来自底层迭代器但尚未被放入适当分区迭代器中的元素需要被缓冲起来；无论如何，最终你仍然需要内部创建某种集合来存储这些数据。

for_each 和 try_for_each


for_each 方法只是对每一个元素都应用了一个闭包处理：

["doves", "hens", "birds"]
    .iter()
    .zip(["turtle", "french", "calling"])
    .zip(2..5)
    .rev()
    .map(|((item, kind), quantity)| {
        format!("{quantity} {kind} {item}")
    })
    .for_each(|gift| {
        println!("You have received: {gift}");
    });

这将会打印出：

You have received: 4 calling birds
You have received: 3 french hens
You have received: 2 turtle doves


这跟简单的 for 循环非常相似，在 for 循环中也可以使用像 break 和 continue 这样的控制结构。不过，像这样连续调用多个适配器的情况，在 for 循环中会显得有些笨拙了。

for gift in ["doves", "hens", "birds"]
    .iter()
    .zip(["turtle", "french", "calling"])
    .zip(2..5)
    .rev()
    .map(|((item, kind), quantity)| {
        format!("{quantity} {kind} {item}")
    })
{
    println!("You have received: {gift}");
}


被绑定模式的变量 gift ，最终可能会位于使用它的循环体非常远的地方。


如果你的终止操作存在出错的可能性，或者你希望提前退出，你可以使用 try_for_each ：

...
    .try_for_each(|gift| {
        writeln!(&mut output_file, "You have received: {gift}")
    })?;

实现自己的迭代器


你可以为自己的类型实现 IntoIterator 和 Iterator 这些特性，这样就能使用本章中介绍的所有适配器与消费者了。此外，还有许多其他库和包中的代码也旨在与标准迭代器接口协同工作。在本节中，我们将展示一个用于遍历范围类型的简单迭代器，然后是一个用于遍历二叉树类型的更复杂的迭代器。

假设我们拥有以下范围类型（从标准库中的 std::ops::Range<T> 类型简化而来）：

struct I32Range {
    start: i32,
    end: i32,
}

对 I32Range 进行迭代需要两个状态：当前的值以及迭代的终止条件。这对于 I32Range 类型来说非常合适，可以使用 start 作为下一个值，而 end 作为终止条件。因此，你可以这样实现 Iterator ：

impl Iterator for I32Range {
    type Item = i32;
    fn next(&mut self) -> Option<i32> {
        if self.start >= self.end {
            return None;
        }
        let result = Some(self.start);
        self.start += 1;
        result
    }
}

这个迭代器会产生 i32 个结果，所以类型是 Item 。当迭代完成之后， next 会返回 None 的值；否则，它会继续产生下一个值，并更新自身状态以准备下一次调用。

当然，一个 for 循环会使用 IntoIterator::into_iter 来将其操作数转换为迭代器。不过，标准库为每一种实现 Iterator 的类型都提供了 IntoIterator 的通用实现，因此 I32Range 可以直接使用。

let mut pi = 0.0;
let mut numerator = 1.0;

for k in (I32Range { start: 0, end: 14 }) {
    pi += numerator / (2 * k + 1) as f64;
    numerator /= -3.0;
}
pi *= 12.0_f64.sqrt();

// IEEE 754 specifies this result exactly.
assert_eq!(pi as f32, std::f32::consts::PI);


不过， I32Range 是一个特例，因为在这里，可迭代对象和迭代器是同一类型的对象。不过，很多情况下情况并不如此简单。例如，这是第 10 章中提到的二叉树类型：

enum BinaryTree<T> {
    Empty,
    NonEmpty(Box<TreeNode<T>>),
}

struct TreeNode<T> {
    element: T,
    left: BinaryTree<T>,
    right: BinaryTree<T>,
}


遍历二叉树的传统方法是使用递归调用。通过堆栈来记录在树中的当前位置以及尚未访问的节点。但在实现 Iterator 时，每次对 next 的调用都必须产生一个值并返回。为了跟踪尚未产生的树节点，迭代器必须维护自己的堆栈。以下是用于 BinaryTree 的一种可能的迭代器类型：

use self::BinaryTree::*;

// The state of an in-order traversal of a `BinaryTree`.
struct TreeIter<'a, T> {
    // A stack of references to tree nodes. Since we use `Vec`'s
    // `push` and `pop` methods, the top of the stack is the end of the
    // vector.
    //
    // The node the iterator will visit next is at the top of the stack,
    // with those ancestors still unvisited below it. If the stack is empty,
    // the iteration is over.
    unvisited: Vec<&'a TreeNode<T>>,
}


当我们创建一个新的 TreeIter 时，其初始状态应该能够生成树中最左边的叶节点。根据 unvisited 栈的规则，它应该先包含那个叶节点，然后是未访问的祖先节点：即树左边缘上的那些节点。我们可以通过从根节点开始遍历树左边缘，并将遇到的每个节点都放入 unvisited 中，从而初始化 unvisited 。为此，我们需要在 TreeIter 上定义一个相关的方法来实现这一功能。

impl<'a, T: 'a> TreeIter<'a, T> {
    fn push_left_edge(&mut self, mut tree: &'a BinaryTree<T>) {
        while let NonEmpty(ref node) = *tree {
            self.unvisited.push(node);
            tree = &node.left;
        }
    }
}


在编写代码时， mut tree 这个变量允许循环在沿着左边缘移动时改变 tree 所指向的节点。不过，由于 tree 是一个共享引用，因此它无法改变节点本身的状态。

有了这个辅助方法之后，我们就可以给 BinaryTree 一个 iter 方法，该方法能够返回树的迭代器表示：

impl<T> BinaryTree<T> {
    fn iter(&self) -> TreeIter<'_, T> {
        let mut iter = TreeIter {
            unvisited: Vec::new(),
        };
        iter.push_left_edge(self);
        iter
    }
}


iter 方法首先创建一个空 unvisited 堆栈的 TreeIter 对象，然后调用 push_left_edge 对其进行初始化。按照 unvisited 堆栈的规则，最左边的节点会被放在最顶端。

按照标准库的惯例，我们可以在对树的共享引用执行 IntoIterator 操作时，同时调用 BinaryTree::iter 函数：

impl<'a, T: 'a> IntoIterator for &'a BinaryTree<T> {
    type Item = &'a T;
    type IntoIter = TreeIter<'a, T>;
    fn into_iter(self) -> Self::IntoIter {
        self.iter()
    }
}


IntoIter 的定义将 TreeIter 指定为 &BinaryTree 的迭代器类型。

最后，在 Iterator 的实现中，我们真正开始遍历这棵树了。就像 BinaryTree 的 iter 方法那样，迭代器的 next 方法也是遵循堆栈的规则来执行的。

impl<'a, T> Iterator for TreeIter<'a, T> {
    type Item = &'a T;
    fn next(&mut self) -> Option<&'a T> {
        // Find the node this iteration must produce,
        // or finish the iteration. (Use the `?` operator
        // to return immediately if it's `None`.)
        let node = self.unvisited.pop()?;

        // After `node`, the next thing we produce must be the leftmost
        // child in `node`'s right subtree, so push the path from here
        // down. Our helper method turns out to be just what we need.
        self.push_left_edge(&node.right);

        // Produce a reference to this node's value.
        Some(&node.element)
    }
}


现在，有了 IntoIterator 和 Iterator 的实现，我们终于可以使用 for 循环来通过引用遍历 BinaryTree 了。接下来，我们可以对“填充二叉树”中的 BinaryTree 使用 add 方法进行处理。

// Build a small tree.
let mut tree = BinaryTree::Empty;
tree.add("jaeger");
tree.add("robot");
tree.add("droid");
tree.add("mecha");

// Iterate over it.
let mut v = Vec::new();
for kind in &tree {
    v.push(*kind);
}
assert_eq!(v, ["droid", "jaeger", "mecha", "robot"]);


图 15-1 展示了当我们在样本树中不断迭代时， unvisited 栈的构成方式。在每一步迭代中，下一个要访问的节点位于栈的顶部，而其下方的所有未访问的祖先节点则被留在了栈中。


所有常见的迭代器适配器以及消费组件都已准备好在我们的系统中使用了：

assert_eq!(
    tree.iter()
        .map(|name| format!("mega-{name}"))
        .collect::<Vec<_>>(),
    vec!["mega-droid", "mega-jaeger", "mega-mecha", "mega-robot"],
);


迭代器体现了 Rust 的编程理念，即提供强大且零成本的抽象结构，从而提升代码的表达能力和可读性。迭代器并非完全替代循环语句，但它们提供了一种功能强大的基础结构，具备延迟评估的特性，并且性能优异。
