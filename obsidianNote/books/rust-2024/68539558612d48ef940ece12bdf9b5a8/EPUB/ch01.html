我们选择用上述三句话作为本书的开头，是有原因的。不过，让我们先来揭开一个谜团吧。下面的 C 程序究竟做了什么？

int main(int argc, char **argv) {
  unsigned long a[1];
  a[3] = 0x7ffff7d48a38UL;
  return 0;
}

今天早上，在杰森的笔记本电脑上运行这个程序后，屏幕上显示的内容是：

undef: Error: .netrc file is readable by others.
undef: Remove 'password' line or make file unreadable by others.


这个程序存在缺陷。数组 a 只有一个元素，因此根据 C 语言的标准，使用 a[3] 会导致未定义的行为。

当使用非可移植或存在错误的程序结构，或者处理有错误的数据时，本国际标准并未对此提出任何要求。


未定义的行为不仅会导致不可预测的结果，而且标准还明确允许程序可以执行任何操作。在我们的例子中，将特定值存储在特定数组的第四个元素中，会导致函数调用栈出现混乱。这样一来，在从 main 函数返回时，程序不会像预期那样正常退出，而是会跳转到 C 标准库中的代码，试图从用户的主目录下的文件中获取密码。这种情况显然不是好事。


在 C 和 C++语言中，有数百条规则用于避免未定义行为。这些规则大多基于常识：不要访问不应该访问的内存；不要让算术运算导致溢出；不要进行除以零的操作等等。不过，编译器并不强制执行这些规则；它没有义务检测到这些明显的违规行为。避免未定义行为的责任完全在于程序员自己。


从经验角度来看，我们程序员在这方面并没有很好的表现。在犹他大学就读时，研究人员彭李对 C 和 C++编译器进行了修改，使得他们翻译出的程序能够报告是否出现了某种未定义行为。他发现，几乎所有的程序都会出现这种情况，包括那些被公认为高质量的项目的程序，这些项目对代码的标准要求也很高。假设在 C 和 C++语言中可以避免未定义行为，就如同仅仅因为了解规则就能赢得国际象棋比赛一样荒谬。


偶尔出现的奇怪消息或系统崩溃可能是技术方面的问题，但那些未被妥善处理的意外行为也一直是安全漏洞的主要来源。早在 1988 年，Morris Worm 病毒就利用了这种技术，在早期的互联网上将病毒从一台计算机传播到另一台计算机。

因此，C 和 C++这两种语言让程序员处于尴尬的境地：虽然这些语言是系统编程领域的行业标准，但它们对程序员的要求却几乎必然会导致不断的崩溃和安全问题。解决这个谜题其实又引出了另一个问题：我们难道不能找到更有效的解决方案吗？

鲁斯特会为您承担一切负担。


我们的回答基于三个引言来构建。第三个引言提到了关于 Stuxnet 的报告。Stuxnet 是一种计算机蠕虫，于 2010 年被发现能够侵入工业控制设备。该蠕虫通过多种手段控制受害者的计算机，其中包括利用嵌入在文字处理文档中的 TrueType 字体中的未定义行为。可以肯定的是，编写该代码的作者并未预料到代码会被以这种方式使用，这说明了不仅仅是操作系统和服务器需要关注安全问题：任何可能处理来自不可信来源的数据的软件都可能成为攻击的目标。


此外，Rust 语言旨在做到既安全又易于使用。为了更精确地控制程序的行为，Rust 对代码提出了比 C 和 C++更严格的限制。不过，这些限制需要时间来适应。不过，总体而言，Rust 语言具有高度的灵活性和可扩展性。这一点可以从用 Rust 编写的代码数量之多以及其应用的广泛领域中得到证明。

根据我们的经验，能够信任语言来发现更多错误，会激励我们尝试更雄心勃勃的项目。当知道内存管理和指针有效性这些问题都得到了妥善处理之后，修改那些庞大而复杂的程序就变得不那么冒险了。而且，当错误带来的潜在后果不会影响到程序中其他无关的部分时，调试过程也会变得更加简单。

当然，仍然有许多漏洞是 Rust 无法检测到的。但实际上，将未定义行为排除在外，确实大大改善了开发的体验，使其变得更加理想。

并行编程正在被逐步改进


在 C 和 C++语言中，正确地使用并发机制是非常困难的。开发者通常只有在单线程代码无法达到他们所需的性能时，才会考虑使用并发技术。不过，第二个引文认为，对于现代计算机来说，并行处理的重要性足以使其成为首选的方法，而不应将其视为最后的手段。

事实证明，那些在 Rust 中确保内存安全性的限制，同样也保证了 Rust 程序不会遇到数据竞争问题。你可以自由地在多个线程之间共享数据，只要这些数据没有发生任何变化。而那些发生了变化的数据则只能通过同步原语来访问。所有传统的并发工具都可用：互斥量、条件变量、通道、原子操作等等。Rust 只是会检查你是否正确地使用了这些工具。

这使得 Rust 成为多线程编程的理想语言。Rust 的生态系统提供了许多库，这些库超越了传统的高并发基础功能，能够帮助你将复杂的任务均匀分配到各个处理器上，同时支持无锁同步机制等先进的功能。

不过，Rust 的运行速度仍然很快。


这终于是我们使用的第一个开场白。Rust 分享了 Bjarne Stroustrup 在他的论文《抽象与 C++机器模型》中所提出的愿景：


一般来说，C++语言的实现遵循“零开销”原则：那些不需要使用的功能，就不需要花费额外的资源来实现。此外，那些确实被使用的功能，其实现方式甚至比手工编码还要更高效。

系统编程往往涉及将机器性能发挥到极致。对于游戏来说，整个机器都应该被用于为玩家创造最佳的体验。而对于网络浏览器而言，浏览器的效率则决定了内容创作者能够处理的内容数量的上限。在机器的固有限制范围内，应尽可能为内容本身保留更多的内存和处理器资源。同样的原理也适用于操作系统：内核应该将机器的资源提供给用户程序，而不是自行消耗这些资源。

但是，当我们说 Rust“速度快”时，究竟是什么意思呢？任何通用编程语言都可以编写速度较慢的代码。更准确地说，如果你愿意投入精力来设计程序，以充分利用底层机器的性能，那么 Rust 会为你提供良好的支持。这种语言的设计考虑了高效的默认行为，同时让你能够控制内存的使用方式以及处理器的资源分配。

锈蚀让协作变得更加容易


我们在这一章的标题中隐藏了第四个引用内容：“系统程序员可以拥有美好的事物。”这指的是 Rust 对代码共享和重用的支持。


Rust 的包管理工具和构建工具 Cargo，使得使用 Rust 公共包仓库 crates.io 上发布的库变得非常方便。你只需要在一个文件中输入库的名称和所需的版本号，Cargo 就会负责下载该库以及它所使用的其他库，然后编译所有库，并将它们链接在一起。可以将 Cargo 视为 Rust 对 NPM 或 RubyGems 的替代方案，它注重版本的规范管理以及可重现的构建过程。
