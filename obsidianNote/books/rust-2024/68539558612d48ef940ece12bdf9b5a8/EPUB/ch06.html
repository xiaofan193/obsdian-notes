在这一章中，我们将介绍 Rust 中的表达式。表达式是构成 Rust 函数主体的基本元素，因此也是大部分 Rust 代码的核心部分。我们还会讨论控制流相关的内容，包括 if 和 match 表达式、循环以及函数调用。在 Rust 中，这些都属于表达式的范畴。此外，我们还将探讨 Rust 中基础运算符在单独使用以及组合使用时的行为。

有一些概念确实属于这一类别，比如闭包和迭代器。这些概念非常重要，我们打算在后面的章节中单独对它们进行详细的介绍。目前，我们的目标是在短短几页的内容中尽可能涵盖所有的语法细节。

一种表达语言


Rust 在外观上类似于 C 语言家族，但这其实是一种设计上的巧妙安排。在 C 语言中，表达式与代码片段之间有明显的区分，代码片段通常看起来像这样：

5 * (fahr-32) / 9


以及那些看起来更像是这样的陈述：

for (; begin != end; ++begin) {
    if (*begin == target)
        break;
}


表达式具有数值，而语句则没有这种特性。


Rust 是一种表达式语言。这意味着它遵循了一种较古老的传统，这种传统可以追溯到 Lisp 时代，当时所有的计算工作都是通过表达式来实现的。


在 C 语言中， if 和 switch 都是语句，它们不会产生任何值，也无法用于表达式的中间部分。而在 Rust 语言中， if 和 match 则可以产生值。在第二章中，我们已经看到过一个 match 表达式，它会产生一个数值。

pixels[row * bounds.0 + column] =
    match escape_time(point, 255) {
        None => 0,
        Some(count) => 255 - count as u8,
    };

可以使用 if 表达式来初始化一个变量：

let status =
    if cpu.temperature <= MAX_TEMP {
        HttpStatus::Ok
    } else {
        HttpStatus::ServerError  // server melted
    };

一个 match 表达式可以作为参数的形式传递给函数或宏。

println!(
    "Inside the vat, you see {}.",
    match vat.contents {
        Some(brain) => brain.desc(),
        None => "nothing of interest",
    }
);


这解释了为什么 Rust 语言中没有 C 语言的三元运算符。在 C 语言中，三元运算符是类似于 if 语句的一种表达式级操作。而在 Rust 语言中，这种操作是多余的： if 表达式已经可以处理这两种情况了。

块


块是 Rust 表达式中不可或缺的组成部分。与其他许多语言一样，块也是由大括号括起来的，可以包含任意数量的声明和表达式。这些块会按从上到下的顺序逐行执行。

一个块可以产生一个值，并且可以在需要值的任何地方使用它：

let display_name = match post.author() {
    Some(author) => author.name(),
    None => {
        let network_info = post.get_network_metadata()?;
        let ip = network_info.client_address();
        ip.to_string()
    }
};


请注意，在 ip.to_string() 方法调用之后并没有分号。大多数 Rust 代码的行都以分号或花括号结尾，这与 C 语言或 Java 类似。如果一个代码块看起来像 C 语言代码，在所有合适的位置都有分号，那么它的运行方式就会类似于 C 语言中的代码块，其值为 () 。正如我们在第二章中提到的，当最后一个代码行的分号被省略时，该代码块的值就会成为其最终表达式的值，而不是通常的 () 。

在一些语言中，比如 JavaScript，你可以省略分号，而语言本身会自动补充分号的位置——这确实是一个小小的便利之处。但 Rust 则不同。在 Rust 中，分号确实具有特定的含义。

let msg = {
    // let-declaration: semicolon is always required
    let dandelion_control = puffball.open();

    // expression + semicolon: method is called, return value dropped
    dandelion_control.release_all_seeds(launch_codes);

    // expression with no semicolon: method is called,
    // return value stored in `msg`
    dandelion_control.get_status()
};

这种通过块来包含声明并在最后产生值的机制确实是一个很棒的功能，使用起来非常自然。不过，有一个缺点就是：如果你不小心忽略了分号，就会出现奇怪的错误信息。

...
if preferences.changed() {
    page.compute_size()  // oops, missing semicolon
}
...

如果你在 C 语言或 Java 程序中犯了这个错误，编译器会直接指出你缺少了分号。而 Rust 语言则会有这样的提示：

error: mismatched types
21 | /     if preferences.changed() {
22 | |         page.compute_size()  // oops, missing semicolon
   | |         ^^^^^^^^^^^^^^^^^^^ expected `()`, found `(u32, u32)`
23 | |     }
   | |_____- `if` expressions without `else` arms expect their
   |          inner expression to be `()`
   |
   = note: expected unit type `()`
                  found tuple `(u32, u32)`
help: consider using a semicolon here
   |
22 |         page.compute_size();  // oops, missing semicolon
   |                            +

Rust 最终建议使用分号来分隔语句，但在此之前，它详细解释了为什么按照原样编写的代码无法正常运行。在那些总是需要分号的语言中，编译器就不需要做太多解释了。

声明/表述


除了表达式和分号之外，一个代码块还可以包含任意数量的声明。最常见的就是 let 声明，它用于声明局部变量。

let name: type = expr;


let 声明允许在不初始化变量的情况下定义变量。之后可以通过后续的操作来初始化该变量。这种方法有时很有用，因为在某些情况下，变量需要从某种控制流结构的某个位置开始初始化。

let name;
if user.has_nickname() {
    name = user.nickname();
} else {
    name = generate_unique_name();
    user.register(&name);
}

在这里，局部变量 name 有两种不同的初始化方式。不过，无论采用哪种方式，该变量都只会被初始化一次。因此，无需对 name 进行声明，也就不需要使用 mut 了。

在变量被初始化之前就使用它是个错误。（这与在变量已经被移动之后还使用该变量的情况类似。Rust 语言确实希望用户只在变量实际存在的时候才使用它们！）

你偶尔可能会看到这样的代码，似乎在重新声明一个已经存在的变量，如下所示：

for line in file.lines() {
    let line = line?;
    ...
}


` let `声明创建一个新的变量，该变量的类型与第一个变量` line `的类型不同。第一个变量` line `的类型是` Result<String, io::Error> `，而第二个变量` line `的类型是` String `。在程序的其余部分，第二个变量的定义会覆盖第一个变量的定义。这种机制被称为“阴影化”，在 Rust 程序中非常常见。代码相当于这样：

for line_result in file.lines() {
    let line = line_result?;
    ...
}


一个块还可以包含物品声明。所谓物品，指的是任何可以在程序或模块中全局使用的声明，比如 fn 、 struct 或 use 这样的声明。

在后面的章节中，我们将详细讨论这些事项。目前来说， fn 已经是一个足够的例子了。任何块都可以包含 fn 元素：

use std::cmp::Ordering;
use std::io;

fn show_files() -> io::Result<()> {
    let mut v = vec![];
    ...

    fn cmp_by_timestamp_then_name(a: &FileInfo, b: &FileInfo) -> Ordering {
        a.timestamp
            .cmp(&b.timestamp)          // first, compare timestamps
            .reverse()                  // newest file first
            .then(a.path.cmp(&b.path))  // compare paths to break ties
    }

    v.sort_by(cmp_by_timestamp_then_name);
    ...
}


当在块内声明一个 fn 时，它的作用域是整个块——也就是说，可以在整个块中使用该变量。但是，嵌套的 fn 无法访问那些处于同一作用域内的局部变量或参数。例如，函数 cmp_by_timestamp_then_name 不能直接使用 v 。不过，Rust 还提供了闭包机制，闭包可以访问外部作用域的变量。更多关于闭包的信息，请参考第 14 章。


一个模块甚至可以包含整个模块。这看起来可能有些过分了——我们真的需要把语言的每个组成部分都嵌套在彼此内部吗？不过，程序员们（尤其是使用宏的程序员）总能找到利用语言所提供的各种正交性的方法。

如果且匹配


if 表达式的形式很常见：

if condition1 {
    block1
} else if condition2 {
    block2
} else {
    block_n
}


每个 condition 都必须是 bool 类型的表达式；只有符合此要求的表达式才能被处理。在 Rust 语言中，数字或指针不会自动转换为布尔值。


else if 这样的注释块，以及最后的 else ，都是可选的。而包含 if 的表达式，如果不存在 else 块，其效果就相当于有一个空的 else 块。


match 表达式类似于 C 语言的 switch 语句，但更加灵活。一个简单的例子：

match code {
    0 => println!("OK"),
    1 => println!("Wires Tangled"),
    2 => println!("User Asleep"),
    _ => println!("Unrecognized Error {code}"),
}


这只是一个 switch 语句可以做到的事情。根据 code 的值，这个 match 表达式的四个分支中恰好有一个会被执行。通配符 _ 可以匹配所有内容。这就像在 switch 语句中的 default: 情况，只不过 _ 模式必须放在最后；如果在其他模式之前使用了 _ 模式，那么它就会优先于其他模式执行。那些模式永远不会匹配到任何内容（编译器会发出警告）。


match 的多样性源于其在每个分支中左侧可以使用的各种不同模式。上面提到的每个模式实际上都只是一个常量整数。我们还展示了 match 的表达式，这些表达式能够区分 Option 值的两种类型。

match params.get("name") {
    Some(name) => println!("Hello, {name}!"),
    None => println!("Greetings, stranger."),
}


这仅仅是模式所能做的事情的一部分而已。模式可以匹配一系列值；可以解析元组；可以匹配结构体中的各个字段；还可以追踪引用、借用值的部分内容等等。Rust 中的模式本身就像一种微型语言。我们将在第十章中详细讨论这些模式。


match 表达式的一般形式为：

match value {
    pattern => expr,
    ...
}


如果 expr 是一个块，那么位于手臂后面的逗号可以省略。

Rust 会依次检查给定的 value 与每个模式是否匹配，从第一个模式开始。当某个模式匹配时，对应的 expr 会被评估，此时 match 表达式就完成了；之后不会再检查其他模式。至少有一个模式必须匹配。Rust 禁止那些无法覆盖所有可能值的 match 表达式。

let score = match card.rank {
    Jack => 10,
    Queen => 10,
    Ace => 11,
};  // error: nonexhaustive patterns

在 if 或 match 表达式中，所有分支都必须产生相同类型的值：

let favorite_number =
    if likes_primes { 31 } else { 57 };  // ok, both i32

let favorite_number =
    if user.is_hobbit() { "eleventy-one" } else { 9 };  // error

let suggested_pet = match favorites.element {
    Fire => Pet::RedPanda,
    Air => Pet::Buffalo,
    Water => Pet::Orca,
    _ => None,  // error: incompatible types
};

let best_sports_team =
    if is_hockey_season() { "Predators" };  // error

（最后一个例子有一个错误，因为在七月时，结果应该是 () 。）

如果允许的话


if 表达式可以使用 let 关键字来实现模式匹配。

if let pattern = expr {
    block1
} else {
    block2
}

给定的 expr 要么与 pattern 匹配，在这种情况下 block1 会被执行；要么不匹配，这时 block2 会被执行。这通常是一种从 Option 或 Result 中提取数据的好方法。

if let Some(cookie) = request.session_cookie {
    return restore_session(cookie);
}

if let Err(err) = show_cheesy_anti_robot_task() {
    log_robot_attempt(err);
    politely_accuse_user_of_being_a_robot();
} else {
    session.mark_as_human();
}

请注意，在最后一个例子中，变量 err 在整个 if 代码块内都是可见的，但在 else 代码块中则不可见。如果这种情况发生，那么匹配模式将无法生效。

可以使用 && 来连接多个条件，如下所示：

if let Some(session) = sessions.get(cookie)
    && session.is_encrypted()
    && let Some(user) = session.logged_in_user()
    && user.is_admin()
{
    ... show admin controls ...
}


实际上，使用 if let 并不是必须的，因为 match 完全可以完成 if let 所能做的事情。简单的 if let 表达式，其实就是带有单一模式的 match 的简写形式。

match expr {
    pattern => { block1 }
    _ => { block2 }
}

更复杂的 if let 表达式，包含多个条件的情况，可以写成嵌套的 match 表达式。

让其他情况发生

当只有一种符合要求的模式时，Rust 提供了一种方便的简写方式，即使用 let ... else 声明：

let pattern: type = expr else {
    divergent block
};

例如，应用程序代码通常需要从表中查找某些数据，如果找不到该数据，则退出程序。使用 let ... else ，可以简洁地表示为：

let Some(team) = teams.get(team_name) else {
    return Err(Error::TeamNotFound);
};
for player in team {
    ...
}


else 块总是用于终止执行的流程，比如 panic、 return 、 break 或 continue 等。这种机制被称为“分流”，下面会进一步讨论。 let ... else 适用于许多常见的控制流场景，但就像 if let 一样，也可以通过 match 来实现相同的功能。

match teams.get(team_name) {
    Some(team) => {
        // ...the rest of the block following the let-else
        for player in team {
            ...
        }
    }
    _ => {
        return Err(Error::TeamNotFound);
    }
}

循环


共有四种循环表达式：

while condition {
    block
}

while let pattern = expr {
    block
}

loop {
    block
}

for pattern in iterable {
    block
}


在 Rust 语言中，循环是一种表达式形式。不过， while 或 for 循环的值始终为 () ，因此它们的价值并不太实用。而 loop 表达式则可以通过 break 关键字来生成值，这一点我们将在下一节中详细了解。


while 循环的行为与相应的 C 语言代码完全相同，只不过 condition 这个变量必须属于 bool 这种确切的类型。


while let 循环与 if let 类似。在每次循环迭代开始时， expr 的值要么与给定的 pattern 相等，此时循环会继续执行；要么不相等，此时循环会终止。可以使用 && 来连接多个条件，就像使用 if 表达式一样。


使用 loop 可以编写无限循环。这样会不断重复执行 block 中的代码，直到达到 break 或 return 的值，或者线程崩溃为止。

一个 for 循环会先计算 iterable 表达式，然后针对结果迭代器中的每个值分别计算一次 block 。可以遍历许多类型的数据，包括所有标准的集合类型，如 Vec 和 HashMap 。标准的 C for 循环结构如下：

for (int i = 0; i < 20; i++) {
    printf("%d\n", i);
}

用 Rust 语言这样编写：

for i in 0..20 {
    println!("{i}");
}


.. 运算符返回一个范围，这个范围是一个包含两个字段的简单结构体： start 和 end 。 0..20 与 std::ops::Range { start: 0, end: 20 } 是相同的。由于 Range 是可迭代的类型，因此可以与 for 循环一起使用。 std::iter::IntoIterator 特性也适用于 Range，我们将在第 15 章中详细讨论这一点。标准的集合类型都是可迭代的，数组和切片也是可迭代的。


为了遵循 Rust 中的移动语义，对某个值进行循环处理时，实际上是消耗了该值的内存空间。

let strings: Vec<String> = error_messages();
for s in strings {          // each String is moved into s here...
    println!("{s}");
}                           // ...and dropped here
println!("{} error(s)", strings.len());  // error: use of moved value

这可能会带来不便。一个简单的解决办法是直接使用对集合的引用来进行循环操作。这样一来，循环变量就相当于指向了集合中的每个元素了：

for s in &strings {         // `strings` is only borrowed here...
    println!("{s}");
}                           // ...nothing is moved or deallocated
println!("{} error(s)", strings.len());  // ok

这里的 &strings 的类型是 &Vec<String> ，而 s 的类型则是 &String 。

对 mut 引用进行迭代时，每个元素都会得到一个 mut 引用：

let mut strings = error_messages();
for s in &mut strings {     // the type of s is &mut String
    s.push('\n');           // add a newline to each string
}


第 15 章详细介绍了 for 循环的用法，并展示了许多使用迭代器的其他方法。

break 和 continue 语句


在 break 表达式中，存在了一个嵌套在循环内的表达式。在许多语言中， break 在 switch 语句中也有特殊的用法，但在 Rust 语言中则没有这种情况。

在 loop 表达式中， break expr 会退出 loop 并为其提供一个值。这个功能比解释起来更容易理解：

// Prompt the user repeatedly until they enter a number.
let party_size = loop {
    let line = input_line("how many?> ");
    if let Ok(num) = line.trim().parse::<u64>() {
        break num;
    }
};

当这个示例到达 break num 时， num 的值就会成为整个 loop 的值。

如果 loop 有多个 break 表达式，那么所有这些表达式都必须提供相同类型的值。这种语法不适用于包含 for 或 while 循环的情境，因为这类循环可以正常结束，而不会导致程序崩溃，从而生成值 () 。

一个 continue 表达式会执行到下一个循环迭代步骤：

// Read some data, one line at a time.
for line in input_lines {
    let trimmed = trim_comments_and_whitespace(line);
    if trimmed.is_empty() {
        // Jump back to the top of the loop and
        // move on to the next line of input.
        continue;
    }
    ...
}


在 for 循环中， continue 会依次处理集合中的下一个元素。如果已经没有更多的元素了，那么循环就会终止。同样地，在 while 循环中， continue 会重新检查循环条件。如果条件变为 false，那么循环也会终止。


循环可以用一个生命周期来标识。在下面的例子中， 'search: 是外部循环 for 的标签。因此， break 'search 指的是离开该循环，而不是进入内部循环：

'search: for room in apartment {
    for spot in room.hiding_spots() {
        if spot.contains(keys) {
            println!("Your keys are {spot} in the {room}.");
            break 'search;
        }
    }
}

标签也可以用于 continue 。

在极少数情况下，如果某个 break 需要同时拥有标签和价值，那么就会写成 break 'label value 的形式。

标记方块


break 这个表达式还有另一个功能。它可以用来提前退出某个代码块。


一个块也可以被赋予一个“生命周期”标签，就像循环一样。然后可以通过 break 来访问该块，从而提前退出该块。在下面的例子中， 'trim 是表示整个块的标签。而 break 则用于直接退出该命名块，并展示其返回值。

let trimmed = 'trim: {
    if string.chars().last() != Some('\n') {
        break 'trim None;
    }
    string.pop();
    if string.chars().last() != Some('\r') {
        break 'trim Some(Newline::Unix);
    }
    string.pop();
    Some(Newline::Windows)
};


同样的逻辑也可以用嵌套的 if 表达式来表达，不过可以说，这个版本的文字表达更清晰易懂。就像一些函数表达式通过添加一些前缀符号后，其可读性会提升一样。

返回表达式


一个 return 表达式会终止当前函数的执行，并返回一个值给调用者。

return 如果没有值的话，相当于 return () 的简写形式。

fn f() {     // return type omitted: defaults to ()
    return;  // return value omitted: defaults to ()
}


在第二章中，我们提到 ? 运算符是一种常见的早期错误处理方式的简写形式，即当发生错误时立即退出程序的手段。我们将在下一章全面介绍 ? 运算符的相关内容。

为什么使用 Rust 会有循环

Rust 编译器的多个组件负责分析程序中的控制流流程：

  • Rust 检查了函数中的每条路径是否返回了预期的类型的值。为了正确完成这一检查，我们需要知道是否真的能够到达函数的末端。

  • Rust 检查了局部变量是否从未被初始化过。这意味着需要遍历函数的每一个路径，以确保没有任何途径可以访问到某个变量，而该变量尚未被初始化。


  • Rust 会提醒用户注意无法访问的代码。如果没有任何路径可以通过函数到达某个位置，那么这段代码就是无法访问的。


这些分析方法被称为“流敏感分析”。其实这并不是什么新概念；在 Java 语言中，多年来一直存在类似于 Rust 中的“确定性赋值”分析机制。

在实施这类规则时，语言需要兼顾简洁性和灵活性。简洁性有助于程序员更容易理解编译器所表达的含义；而灵活性则能避免产生不必要的错误警告，同时也能防止编译器错误地拒绝看似完全安全的代码。Rust 选择了简洁性作为目标。它的流控制分析方式并不检查循环条件，而是简单地假设程序中的任何条件都可能是真或假。

这会导致 Rust 拒绝执行某些安全的程序：

fn wait_for_process(process: &mut Process) -> i32 {
    while true {
        if process.wait() {
            return process.exit_code();
        }
    }
}  // error: mismatched types: expected i32, found ()

这里的错误是不正当的。这个函数只能通过 return 表达式来终止，因此 while 循环没有产生 i32 这一结果并不重要。

不过，如果你将 while true 替换为 loop ，那么代码就能正常编译了。Rust 并不担心在还没有生成 i32 这个值时就到达函数的末尾。因为它知道永远无法到达函数的末尾。控制流也永远不会超出 loop 的边界。


所以在 Rust 语言中，这些表达式并没有常规的类型。那些无法正常完成计算的表达式会被赋予特殊的类型 ! ，并且它们可以免于遵循“类型必须匹配”这一规则。你可以在 std::process::exit() 的函数签名中看到 ! 的例子：

fn exit(code: i32) -> !


! 表示 exit() 永远不会返回值。这是一个发散函数。

你可以使用相同的语法来编写自己的函数。在某些情况下，这样做是完全合理的：

fn serve_forever(socket: ServerSocket, handler: ServerHandler) -> ! {
    socket.listen();
    loop {
        let s = socket.accept();
        handler.handle(s);
    }
}

当然，如果函数在正常情况下能够正常返回结果，那么 Rust 会认为这是一个错误。

禁止使用的代码块


const 块类似于普通的块，但它是在编译阶段运行的。在大多数情况下，声明一个常量更为清晰明了。

let angle = const { PI / 6.0 };  // const block

const ANGLE: f64 = PI / 6.0;     // constant

这两个变量都保证在编译时进行计算。不过， ANGLE 是可以全局定义的，并且可以在整个代码中重复使用。而局部变量则无法如此使用。此外， const 块作为一种性能优化手段，其实并没有太大的实用价值。编译器会自动优化那些不必要的运行时计算，无需用户特别指示；在这个例子中，即使没有使用 const 块，除法操作仍然会在编译时完成，即使在调试模式下也是如此。

关于 const 块的有趣之处在于，编译器会检查代码是否能够成功执行。如果 const 块发生异常，它会被视为编译时错误，而不是运行时异常。这使得 const 块适用于编译时断言的场景。

fn allocate_memory<T>(alloc: &mut MyAlloc, value: T) -> MyBox<T> {
    const {
        // Enforce some limitations of the allocator.
        // Compilation fails if either assertion fails.
        assert!(size_of::<T>() > 0);
        assert!(size_of::<T>() <= MyAlloc::MAX_SIZE);
    }
    ...
}


最后， unsafe 符号用于放弃 Rust 的安全保证机制，转而采用更简洁的语言风格以及更强大的库功能，比如直接操作指针。关于不安全代码的内容，我们将在第 23 章中进行讨论。

在掌握了 Rust 中控制流相关的所有基础概念之后，我们可以进一步探讨在控制流中常用的更精细的表达式，比如算术运算符和函数调用。

函数与方法调用


在 Rust 语言中，调用函数和方法的语法与许多其他语言相同：

let x = gcd(1302, 462);  // function call

let room = player.location();  // method call


在第二个例子中， player 是一个属于自定义类型 Player 的变量，而 Player 则包含一个自定义的 .location() 方法。当我们在第 9 章讨论用户定义类型时，会介绍如何定义自己的方法。

在 Rust 中，通常会明确区分引用及其所指向的值。例如，如果你将一个 &i32 传递给一个期望接收 i32 参数的函数，那么就会出现类型错误。而 . 运算符则稍微放宽了这些规则。在 player.location() 方法的调用中， player 可能是 Player ，即类型 &Player 的引用；也可能是类型 Box<Player> 或 Rc<Player> 的智能指针。 .location() 方法可能会以值传递或引用传递的方式传递该对象。同样的 .location() 语法适用于所有情况，因为 Rust 的 . 运算符会根据需要自动解引用 player 或借用其引用。

第三种语法用于调用相关函数，例如 Vec::new() :

let mut numbers = Vec::new();  // associated function call


这些类似于面向对象语言中的静态方法：普通方法是对值进行调用（比如 my_vec.len() ），而相关的函数则是对类型进行调用（比如 Vec::new() ）。

当然，方法调用可以链式调用：

// From the Actix-based web server in Chapter 2:
server
    .bind("127.0.0.1:3000")
    .expect("error binding server to address")
    .run()
    .await
    .expect("error running server");

Rust 语法的一个特点是在函数调用或方法调用中，通常用于表示通用类型的语法 Vec<T> 并不适用：

return Vec<i32>::with_capacity(1000);  // error: something about chained comparisons

let ramp = (0..n).collect<Vec<i32>>();  // same error


问题在于，在表达式中， < 代表的是“小于”运算符。Rust 编译器的帮助提示，在这种情况下，应该写成 ::<T> 而不是 <T> ，这样就能解决该问题了。

return Vec::<i32>::with_capacity(1000);  // ok, using ::<

let ramp = (0..n).collect::<Vec<i32>>();  // ok, using ::<


在 Rust 社区中，符号 ::<...> 被亲切地称为“涡轮鱼”。

或者，通常也可以省略类型参数，让 Rust 自行推断它们的类型：

return Vec::with_capacity(10);  // ok, if the fn return type is Vec<i32>

let ramp: Vec<i32> = (0..n).collect();  // ok, variable's type is given

在可以推断出类型的情况下，省略这些类型是一种良好的设计风格。

领域与元素


结构体中的字段可以使用熟悉的语法来访问。元组的情况也是类似的，只是它们的字段是带有数字的编号，而不是具体的名称。

game.black_pawns   // struct field
coords.1           // tuple field

如果点左边的数值是一个引用或智能指针类型，那么它会自动被解引用，就像方法调用一样。

方括号用于访问数组、切片或向量中的元素：

pieces[i]          // array element

括号左侧的值会自动解引用。

从数组或向量中提取一部分数据是非常简单的操作：

let second_half = &game_moves[midpoint..end];


.. 运算符允许省略任一操作数；根据存在的操作数不同，它可以生成四种不同类型的对象。

..      // RangeFull
a..     // RangeFrom { start: a }
..b     // RangeTo { end: b }
a..b    // Range { start: a, end: b }


后两种形式属于“独占”形式（或半开放形式）：即末端数值并不包含在所表示的范围内。例如， 0..3 这个范围包含了 0 、 1 和 2 这些数值。


..= 运算符生成的区间包括端点：即区间不仅包含起始值，也包含结束值。

..=b     // RangeToInclusive { end: b }
a..=b    // RangeInclusive::new(a, b)

例如，范围 0..=3 包含了数字 0 、 1 、 2 和 3 。

只有包含起始值的范围才是可迭代的，因为循环至少需要有一个起始点。但在数组切片中，这六种形式都很有用。如果省略了范围的起始点或结束点，那么默认会使用数据切片的起始点或结束点作为起始点。

因此，快速排序的实现，这种经典的分治排序算法，其执行过程或许可以这样描述：

fn quicksort<T: Ord>(slice: &mut [T]) {
    if slice.len() <= 1 {
        return;  // Nothing to sort.
    }

    // Partition the slice into two parts, front and back.
    let pivot_index = partition(slice);

    // Recursively sort the front half of `slice`.
    quicksort(&mut slice[..pivot_index]);

    // And the back half.
    quicksort(&mut slice[pivot_index + 1..]);
}

引用运算符


地址操作符 & 和 &mut 的相关内容在第五章中有介绍。


一元的 * 运算符用于访问由引用指向的值。正如我们所看到的，当使用 . 运算符访问字段或方法时，Rust 会自动跟踪引用。因此，只有在需要读写该引用所指向的整个值时，才需要使用 * 运算符。

例如，有时迭代器会返回引用类型的数据，但程序仍然需要这些基础值。

let padovan: Vec<u64> = compute_padovan_sequence(n);
for elem in &padovan {
    draw_triangle(turtle, *elem);
}

在这个例子中， elem 的类型是 &u64 ，所以 *elem 就是 u64 。

算术运算、位运算、比较运算符以及逻辑运算符


Rust 中的二元运算符与其他许多语言中使用的运算符类似。为了节省时间，我们假设读者已经熟悉其中一种编程语言，然后重点介绍 Rust 与常规语法不同的几个地方。


Rust 提供了常见的算术运算符，如 + 、 - 、 * 、 / 和 % 。正如第 3 章所述，在调试版本中，系统能够检测整数溢出情况，并在出现溢出时引发恐慌。标准库还提供了类似 a.wrapping_add(b) 之类的函数，用于处理未检查过的算术运算。


整数除法会趋向于零，而将一个整数除以零会在包括发布版本在内的所有环境中引发恐慌。整数有一个方法 a.checked_div(b) ，它返回一个 Option 值（如果 b 为零，则返回 None 值），该方法永远不会引发恐慌。

一元运算符 - 用于否定一个数字。除了无符号整数类型之外，所有数字类型都支持这一运算符。不过并没有对应的一元运算符 + 。

println!("{}", -100);     // -100
println!("{}", -100u32);  // error: can't apply unary `-` to type `u32`
println!("{}", +100);     // error: leading `+` is not supported


在 C 语言中， a % b 函数用于计算有符号余数或模数，其中结果的方向与左手边的操作数相同。需要注意的是， % 函数不仅可以用于整数，也可以用于浮点数。

let x = 1234.567 % 10.0;  // approximately 4.567


Rust 还继承了 C 语言的位运算运算符，包括 & 、 | 、 ^ 、 << 和 >> 。不过，Rust 在表示位运算的“非”操作时，使用的是 ! 而不是 ~ 。

let hi: u8 = 0xe0;
let lo = !hi;  // 0x1f

这意味着 !n 不能用于整数 n 上，来表示“n 等于零”。在这种情况下，应该使用 n == 0 来表示这个意思。


与 C 语言不同，位运算的优先级高于比较运算。因此，如果你写的是 x & BIT != 0 ，那就意味着你要执行的是 (x & BIT) != 0 ，这更符合你的意图。这种方式比 C 语言中的解释要实用得多——C 语言中的解释是测试错误的位，而位运算则能确保只测试正确的位。


Rust 中的比较运算符包括 == 、 != 、 < 、 <= 、 > 和 >= 。与算术运算符类似，这些运算符也只能用于相同类型的两个数值。对于字符串、元组、数组、切片和向量来说，比较时遵循字典顺序。而比较两个引用时，实际上就是比较它们的引用对象。


Rust 还提供了两个短路逻辑运算符 && 和 || 。这两个运算符的操作数必须具有类型 bool 。

任务/作业


= 运算符可以用于将值赋给 mut 变量及其字段或元素。不过，在 Rust 语言中，这种赋值操作并不像在其他语言中那样常见，因为默认情况下变量都是不可变的。


如第 4 章所述，如果值的类型不是 Copy 类型，那么赋值操作会将值移动到目标位置。此时，该值的所有权从源对象转移到了目标对象。如果目标对象之前存在值，那么这些旧的值将被丢弃。

支持复合赋值操作：

total += item.price;


这相当于 total = total + item.price; 。其他运算符也支持使用： -= 、 *= 等。所有运算符的完整列表可以在本章前面的表 6-2 中找到。

与 C 语言不同，Rust 不支持链式赋值操作：你不能这样写 a = b = 3 来将值 3 同时赋给 a 和 b 。在 Rust 中，赋值操作非常少见，所以你不会错过这种简写方式。

Rust 语言中并没有 C 语言中的递增和递减运算符 ++ 和 -- 。

类型转换


你可以使用 as 关键字将一个类型的值转换为另一个类型。这种操作被称为类型转换。

let x = 17;              // x is type i32
let index = x as usize;  // cast to usize

允许使用几种不同的石膏固定方式：

  • 数字可以从任何内置的数字类型中选取，并用于其他任何用途。


    将浮点类型转换为整数类型时，数值会向零方向四舍五入： -1.99 as i32 的值变为 -1 。如果数值太大，无法容纳在整数类型中，那么强制类型转换会生成整数类型所能表示的最接近的值： 1e6 as u8 的值变为 255 。


  • 类型 bool 或 char 的值，或者类似 C 语言的 enum 类型的值，可以转换为任何整数类型。（我们将在第十章中讨论枚举类型。）


    不允许进行非预期类型的转换。因为 bool 、 char 和 enum 这些类型的数值都有其特定的限制条件，这些限制需要在运行时进行验证。例如，禁止将 u16 类型的值转换为 char 类型，因为某些 u16 类型的值，如 0xd800 ，会对应到 Unicode 代理码点，因此无法成为有效的 char 类型值。不过，有一个标准的方法 char::from_u32() 可以执行这种运行时检查，并返回一个 Option<char> 类型的值；不过，这种转换已经变得非常罕见了。我们通常一次性转换整个字符串或数据流，而处理 Unicode 文本的算法往往比较复杂，因此最好将这些任务留给专门的库来处理。

    作为例外， u8 类型可以被强制转换为 char 类型，因为 0 到 255 之间的所有整数都是 char 类型可以表示的有效 Unicode 代码点。


  • 一些使用原始指针类型的赋值操作也是被允许的。详见“原始指针”部分。

有一些涉及引用类型的转换非常简单，语言甚至可以在不进行类型转换的情况下完成这些操作。一个简单的例子就是将一个 mut 引用类型的值转换为非 mut 引用类型的值。

不过，还有几个更重要的自动转换操作可以执行：

  • 类型 &String 的值会自动转换为类型 &str ，无需进行类型转换。

  • 类型 &Vec<i32> 的值会自动转换为 &[i32] 格式。

  • 类型 &Box<Chessboard> 的值会自动转换为 &Chessboard 格式。


这些被称为“去强制转换”，因为它们适用于那些实现了 Deref 内置特性的类型。 Deref 强制转换的目的是让智能指针类型，比如 Box ，尽可能模拟原始值的特性。由于有了 Deref 的支持，使用 Box<Chessboard> 基本上就跟使用普通的 Chessboard 一样。


用户定义的类型也可以实现 Deref 特性。当你需要创建自己的智能指针类型时，可以参考“Deref 和 DerefMut”相关内容。

关闭


Rust 语言中有闭包机制，可以将函数式元素以轻量级的形式进行封装。一个闭包通常由一个参数列表组成，参数列表被放在竖线之间，然后是一个表达式。

let is_even = |x| x % 2 == 0;

assert_eq!(is_even(14), true);

Rust 能够推断出闭包的参数类型和返回类型。你也可以像定义函数一样明确写出这些类型。如果你确实需要指定返回类型，那么闭包的代码体必须是一个代码块，这样才能保持语法上的清晰性。

let is_even = |x: u64| -> bool x % 2 == 0;  // error

let is_even = |x: u64| -> bool { x % 2 == 0 };  // ok


闭包是 Rust 中非常有趣的特性之一，关于它们还有更多值得讨论的内容。我们将在第十四章中详细阐述这一点。

向前迈进

表达式可以被视为“运行的代码”。它们是 Rust 程序中那些会编译成机器指令的部分。不过，这些表达式在整个语言中只占很小的一部分。


接下来，我们将用几章来讨论这一领域的特性：模块和容器，它们为程序提供了结构支持；还有结构体和对象，它们同样用于管理数据。
